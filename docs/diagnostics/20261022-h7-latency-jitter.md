2026-10-22。仅离线处理三段已有录制；未连接硬件、改固件、改训练参数或启动训练。这里的抖动指耗时/周期的波动，不是传感器数值噪声。

## 主样本结果

下表限定 RL 已投入、fault=0、稳定 NORMAL；投入后首1秒另归 `startup_*`，前后镜像状态不一致的区间另列。阶段和投入状态是100Hz镜像上下文；高频CONTROL仍使用自身记录的策略、故障和出力标志分组。

单位均为 μs；标准差使用总体标准差。P99表示99%的**已观察样本**不超过该值，不是最坏情况保证。

| 测点 | 样本数 | 均值 | 标准差 | P99 | 最大值 | 峰峰值 |
|---|---:|---:|---:|---:|---:|---:|
| 网络调用 | 2532 | 715.324 | 2.680 | 720.000 | 721.000 | 15.000 |
| 控制分发 | 25327 | 14.373 | 1.173 | 18.993 | 23.513 | 10.010 |
| DJI CAN HAL调用 | 25327 | 1.551 | 0.367 | 1.623 | 10.044 | 8.655 |
| 控制分发周期 | 25325 | 2000.000 | 1.989 | 2005.142 | 2009.531 | 18.949 |
| DJI CAN调用周期 | 25325 | 2000.000 | 2.437 | 2005.694 | 2010.089 | 20.260 |
| 控制拍左轮反馈数据龄 | 25327 | 1441.422 | 269.910 | 1946.740 | 2076.000 | 1124.000 |
| 控制拍右轮反馈数据龄 | 25327 | 1443.631 | 273.430 | 1951.000 | 2117.000 | 1166.000 |

- 控制周期相对2ms的偏差范围为 **−9.418～+9.531 μs**。这是分发起点的周期波动，不是整个任务唤醒时间，也不是传感器/电机延迟。
- 缓存到动作发布的2532个毫秒差值均为0，即每个已观察差值对应的真实区间小于1ms；不能称耗时为0。策略发布的2530个可配对间隔均读为20ms，也无法分辨亚毫秒抖动。
- 按策略序号和动作值匹配的输出，动作年龄为 **6/16ms**，共5067个稳定NORMAL快照。这是100Hz镜像对50Hz动作保持过程的取样；不能称为首次应用延迟或机械响应延迟。
- 镜像时刻IMU及双轮反馈数据龄读为0/1ms，四髋均为1ms。它们均按毫秒向下取整；读数标准差为0不能证明真实数据龄不变。控制拍双轮数据龄在另一个测点读取，不能与镜像数据龄直接相加。
- CONTROL起点在PD计算之后，结束在下发和镜像发布后；14.373μs不包含PD计算，也未覆盖记录入队之后的所有开销。网络调用内部可能受抢占影响，其波动没有进一步分解为计算和抢占两项。
- CAN HAL成功仅证明入队；唯一CONTROL时间包含区间不是调用来源证明。附加指标 `dispatch_to_hal_begin_us`仅解释为区间内起点偏移。

各会话保留每项的最小值、中位数、均值、标准差、P95、P99、最大值、峰峰值、样本数；分状态统计在 `statistics.csv/json`，逐连续区间统计在 `segment-statistics.json`。`segments.csv`及各逐样本CSV提供区间号、原始事件编号、序号和板端时间。每项最大值附CSV行号，可回查原始记录。

主样本全文件仍保留历史缓存序号缺口5115834、队列丢弃增量2，不能改写为完整通过。按首末镜像板端毫秒范围裁剪后的当前记录为一个连续区间；主样本128条区间外原始记录仍在 `full-output/outputs.csv` 中。对照2的9次额外失败发生在首镜像范围之前，故当前区间1491次与全文件1500次不矛盾。所有会话均不跨原始序号缺口、镜像缺口、重连或状态切换计算普通周期。

旧故障数据中的反馈数据龄可达到秒级，这是失联后反馈变旧，不能混入正常运行的“随机延迟噪声”。恢复阶段切换时，非零请求间隔可出现约6ms；实际分发记录和归零记录仍单独保留，不将其解释为6ms调度停顿。

校验包括：原始流SHA-256、事件完整性、模型/机器配置归档哈希、重复快照内容一致、策略序号及动作值一致、分组样本数守恒，以及全部948项分组最大值对原始字段/周期端点的回查。有限合成检查覆盖时间戳/序号回绕、缺号、区间/状态边界、CRC拒绝、队列丢弃计数与未知数据龄；通过不代表硬件时序或行为验收。

本地 `task_policy.c`、`vofa_debug.c`、`rl_policy.c`和时基源码与旧会话预期固件清单匹配；`task_actuation.c`及`output_capture.h`已有版本差异，逐文件比较结果保留在会话 `source_comparison`。计时字段含义同时核对[输出记录接口](../interfaces/20261021-h7-output-capture-v1.md)、[USB镜像v2接口](../interfaces/20261020-h7-ros-usb-mirror.md)及实际解码布局。主样本没有固件manifest；其他会话的manifest也只是预期构建信息，均不能当作板端启动身份认证。

## 尚不能测出的延迟

| 环节 | 缺失测点 |
|---|---|
| IMU/编码器内部采样和滤波 | 实际采样时间、滤波前后时间或同步硬件边沿 |
| 源头到H7接收/解析 | 源头采样与接收/解析起止的同钟配对 |
| 调度等待、观测构造、PD分别耗时 | 逐环节独立起止、贯穿编号 |
| 四腿逐路CAN提交 | 每路DM发送起止及控制/动作序号 |
| CAN排队/仲裁/电气发送与送达 | Tx完成事件或共同时基的总线分析记录 |
| 电机收到命令至电流/力矩生效 | 内部时间戳或同步独立电流/轴端力矩测量 |
| 完整物理闭环延迟和抖动 | 贯穿源头采样、对应动作和实际力矩的编号与同步测点 |

本报告没有把这些缺项估为0，也没有用USB/SSH接收间隔、轮速互相关或受绳索约束的机械运动补出“全链路延迟”。
