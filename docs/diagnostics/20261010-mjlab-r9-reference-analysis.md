# r9 与 wheelleg_RL 训练结果差异分析

日期：2026-10-10。训练仓分支 `26_wheelleg`，HEAD `58947e8fabc4683b2025d42bda742b06c84dc566`，包含现有未提交 r9 改动。本次只核对实现、训练快照和模型，运行参考项目官方评估并保存诊断；没有修改训练实现或启动训练。

## 结论

此前“全部对齐”的描述过于宽泛。普通 PPO 配置相同，不等于训练历史、物理模型和当前策略接口相同。最关键的已核实差异是：参考策略累计训练 5163 轮，并继承已有策略、价值网络和优化器；本仓 r9 从随机权重开始，只训练 1000 轮。除此之外，关节附加惯量、阻尼、摩擦、闭链响应和三项按用户要求恢复的训练设置仍不同。

这足以说明两个实验没有完整复现同一训练条件。现有证据不能给各差异分配因果比例，也不能断言某一个参数是唯一原因。

“更多训练就一定解决”尚无证据；应先复现初始化及阶段过程，再评估累计轮数的影响。

## 2. 物理模型仍不同

以下来自两个实际编译的 MuJoCo 模型，按关节名称匹配，非只看配置文本：

| 参数 | 参考 | 本仓 |
|---|---:|---:|
| 四个主动腿关节 armature | 0.015795 | 0 |
| 被动腿关节 armature | 0.0001 | 0 |
| 主动腿关节模型阻尼 | 0 | 0.03 |
| 被动腿关节模型阻尼 | 0.01 | 0.03 |
| 腿关节 frictionloss | 0 | 0.015 |
| 轮关节模型阻尼 | 0 | 0.002 |
| 轮关节 frictionloss | 0 | 0.001 |
| 六个闭链 connect 的 solref | [0.01, 1] | [0.005, 1] |

这里的模型被动阻尼与控制器 PD 的 D 增益是不同字段；两边腿 PD 同为 60/2。

`armature` 是关节上的附加惯量，常用于表示电机转子经减速器折算的惯量；相同力矩下它会改变运动响应。正数格式的 `solref` 第一项控制约束时间常数，本仓较小，约束响应更快、更硬。定义见 [MuJoCo armature 文档](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-joint-armature)和[求解器参数文档](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)。

这些差异会改变策略每步获得的状态与奖励，但本次未逐项替换测试，不能断言它们各自导致了多少失败。本仓 solref=0.005 来自此前 GPU 闭链偏差修复，不能在没有复查闭链误差的情况下直接恢复 0.01。

同时核对到了相同部分：

- 总质量均为 13.39458410046886 kg。
- 19 个共同关节的轴向、位置和限位一致，数值差不超过 1e-10。
- 四个腿电机默认零点一致。
- 六个 connect 的 solimp 一致。
- 初态库各侧 normal/positive/negative 的 1024×9 数组及相关采样边界一致，最大绝对差为 0。
- 两边 STL 文件的二进制哈希存在差异，但全部 15 个碰撞 mesh 转换到对应刚体坐标系后的点云几何一致，Hausdorff 距离为 0。不能据文件哈希不同推断机器人几何不同。

逐关节数据及碰撞点云比较保存在[差异证据 JSON](20261010-mjlab-r9-reference-differences.json)。

## 3. 当前 r9 已有三项明确的训练接口差异

| 项目 | 参考主线 | 本仓 r9 |
|---|---|---|
| 模式观测 | 固定 NORMAL：[1,0,0,0,0,0,0] | 动态 normal/recover，含目标高度和状态时间 |
| 新增膝限位奖励权重 | -0.5 | 0 |
| 六维动作及关节观测顺序 | lf0、lf00、lfwheel、rf0、rf00、rfwheel | lf0、lf00、rf0、rf00、lfwheel、rfwheel |

这三项是后续按用户要求恢复的设置，故当前训练不再与参考主线完全相同。模式改变了策略输入，膝惩罚关闭改变了优化目标；动作顺序需按契约转换。本仓已有对应重排及实体关节检查，现有证据未发现顺序改回后发生了错位驱动。直接加载参考检查点仍须处理观测和动作契约差异。

## 4. 已一致的训练配置与优化结果的区别

核对实际保存的 PPO 配置，算法字段相同；actor 35 维、critic 78 维、动作 6 维，物理步长 0.002 秒、控制降采样 10、腿 PD 60/2、轮速度反馈 0.1，以及当前恢复阶段的命令范围、延迟和随机化设置已对齐。除上面的膝惩罚外，其余 26 个奖励项的权重和实现已对齐。导入的 14 个参考文件哈希仍匹配参考源码，没有发现参考代码在导入后漂移。

参考最终优化器学习率约 1e-5，本仓约 5.7665e-4。两边使用同样的自适应 KL 学习率机制，但不同轨迹、既有优化器状态和训练阶段会形成不同的最终学习率；这不是初始配置漏抄的证明。

即使完全相同的配置和初始化也不能仅凭一次随机训练要求模型权重逐位一致，但目前的系统性失败应优先排查上述已确认的实验差异，不能用随机性解释掉。

## 建议的排查顺序

1. 核对真实电机及传动参数，先决定主动关节 armature、被动阻尼与摩擦应取哪个物理值；保留真实机器人几何。物理参数修改后重做闭链误差与随机初态检查。
2. 复现参考的基础训练→混合初态→恢复续训过程，并记录累计轮数及 actor/critic/优化器初始化来源。若使用参考权重，先完成两侧观测、动作和模型契约的兼容核对。
3. 使用相同策略和评估初态，逐项比较物理参数、动态模式、膝惩罚，避免一次改多项后把结果归因到单一改动。

本次未执行这些修改或新训练。
