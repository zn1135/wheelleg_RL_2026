# 2000→3000轮地面初态双轮平衡退化审计

2026-10-12，针对用户指出的“2000轮还能从地面初态保持双轮平衡，续训后退化”，核对实际checkpoint配置，并执行无学习的配对反事实回放。本次只增加诊断脚本与记录，没有修改训练配方、启动训练或覆盖历史模型。

## 结论

本次续训切换了训练目标、课程、命令、模式观测和终止规则。同一批64个地面初态中，2000轮能持续双轮平衡的58个样本，3000轮保留56个，丢失样本0和55，没有新增成功样本。样本0从双轮承担整机重量变成非轮部件撑地，确有行为退化；本批证据只覆盖这两个丢失样本，不证明全部初态或训练随机化条件都退化。

反事实回放表明，丢失能力存在于续训后的actor权重：3000轮切回固定NORMAL输入也不能恢复。动态模式会改变动作，但本批2000轮固定/动态输入都成功58个，3000轮动态输入还比固定输入多成功1个。因此不能把本次退化归因为单独打开RECOVER标志。

最值得怀疑的训练原因，是从已经具备低位双轮平衡的2000轮模型重新学习“只扶正”，同时移除高度与四项速度跟踪目标，再用容易饱和、缺少承重要求的支撑奖励训练。它们共同改变了优化目标，并没有把旧模型的成功初态作为必须保留的行为门槛。具体哪一项贡献最大，尚未做训练消融，不能只凭回放认定某一个奖励是唯一原因。

## 续训具体改了什么

实际checkpoint的`infos.environment`和run中的`runner.json`递归差异见[metadata-diff.json](../../artifacts/recovery-regression-paired-20261012/metadata-diff.json)，以下结合对应奖励源码解释。

| 改动 | 对学习目标的影响与证据边界 |
|---|---|
| 从2000轮重新开始整批扶正→平衡→高度课程 | 前100次更新只要求机身扶正，允许非轮撑地；之后约900次更新训练平衡，没有进入高度阶段。旧的双轮恢复行为没有保留门槛。 |
| 扶正和平衡阶段关闭两项高度奖励 | 本次1000轮高度奖励全程为0。原先推动机体离开低位的高度目标消失；这解释了高度没有改善，但单独不能证明双轮能力损失。 |
| 平衡阶段新增权重+2的轮支撑奖励 | `min(clamp(Fz/5,0,1))*upright`在两轮各5 N时饱和。两轮只承担约10 N、远小于131.4 N整机重量也可能拿满；奖励没有直接要求非轮卸载，也没有把稳定速度条件纳入该奖励。 |
| 扶正阶段关闭`undesired_contact` | 正立但仍撑地能够完成阶段、取得姿态收益；从已具备双轮平衡的模型重启此阶段，存在把行为往撑地状态推的风险。平衡阶段已恢复接触惩罚，因此不能声称后900轮也完全没有触地代价。 |
| 所有阶段固定零前进/偏航命令，关闭四项速度跟踪奖励和特殊命令 | 改变训练分布，移除原前进/偏航误差的反馈；静止线速度、竖直速度、横向角速度等惩罚仍保留。零速还使原姿态公式中`orientation_gain=2*exp(-vx²/3)+2`固定为最大4，权重未变也会改变相对惩罚。 |
| 姿态公式补入倒置区分 | 指数项乘`clamp((1-gz)/2,0,1)`，平方项各加`0.5*(gz+1)^2`。正确区分倒置，但也使继承的critic价值目标改变；其单独影响尚无训练消融。 |
| 触地/大倾斜由连续0.4秒终止改为允许恢复20秒 | 改变失败轨迹与reset分布；数值异常仍立即终止，期末当前阶段未完成仍判失败。−200权重仍由RewardManager乘0.02秒，单次失败贡献−4；只在期末处罚，不能保证之前的撑地收益不会影响策略。 |
| 固定模式改为动态模式，旧严格组合指标改为分阶段指标 | 存在观测与价值分布变化风险，但本批反事实没有显示动态槽导致退化。指标名称或门槛变化本身也不能替代物理受力证据。 |

这些变化同时发生，PPO优化新目标不保证原58个成功初态全部保留。现有证据支持“新目标续训后部分恢复行为遗忘”，并未确定单一奖励的训练因果贡献。

## 核实未变化的部分

- 重新逐项比较源2000模型与真实run的`model_resume_initial.pt`：actor、critic、Adam完全一致。排除启动时重新随机初始化或漏载优化器。
- `runner.json`仅实验名和run名不同，其余PPO/网络参数一致。源与最新checkpoint优化器学习率均1e-5，保持自适应配置。
- 实际环境`actions`、`scene`、`observations`、`sim`、`decimation`、回合长度、seed一致；已有reset/随机化事件一致，仅新增课程step事件。因此初态仍普通50%/地面50%，地面机体零姿态，PD、动作顺序和物理步长未改。
- 三个冻结目录XML SHA256均为`42a1b937b83ca034d4913306aeca5b219c3cd1c5a0bbd57b0220d7f5d5c826e0`；实体模型、PD、Huananhu动作适配、初态缓存、随机化、观测等共享源码哈希均相同。无辅助力、膝限位惩罚或默认角惩罚被重新打开。
- 最近准备的`huananhu-v14-wheel-support`承重配置尚未进行训练，不可能是这次已经完成的3000轮退化原因。本次只使用它的只读传感器与评价判据。
- XML已做几何/静力检查，0.27/0.30/0.34 m可达；这不等于自由动态稳定，但2000→3000的配置与资产证据不支持“续训改坏XML”解释。见[XML审计](20261012-mjlab-wheel-support-xml-height-audit.md)。

## 建议下一步

保留2000轮作为低位双轮恢复的对照与修复起点。下一次方案应先维持它已有的双轮对地承重能力，再加入高度目标：避免重新经过只奖励扶正、允许撑地的阶段；承重判据不限制腿关节角。每次只改变一个学习目标，用本批相同初态检查原58个成功样本是否丢失，再决定后续课程。

不建议仅切回固定模式或直接增加轮数来修复：前者已在反事实中不能挽回3000轮失败样本，后者没有解决奖励与目标之间的差距。下一组训练需另行确定配置、迁移接口和轮数，本次没有启动。
