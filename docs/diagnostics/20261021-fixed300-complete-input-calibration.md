## 输入、时间与自由积分

正常H7链路为原始策略动作→动作缩放后的目标轮速→原0.1轮速P输出→模型/最终限幅及坐标映射→门控后名义Nm→DJI刻度/量化→实际CAN四槽提交。台架直接提供±3名义Nm，绕过策略/轮速P，仍走最终驱动。代码位置/单位/极性已沿实际路径核对，详见前次报告和[完整输出接口](../interfaces/20261021-h7-output-capture-v1.md)。

本次使用每实际分发拍CONTROL门控后的请求（台架约1kHz），仅将固件坐标通过既有model_sign映射一次；**不再乘电流换算、齿比或重新跑策略**。实际CAN提交单独记录，HAL返回成功只证明提交接口成功，不证明电机收到或轴端达到请求力矩。控制时间用板端begin_ns，反馈用配对接收年龄对齐；这是接收源位置，不能把USB/SSH读返回间隔或接收年龄解释成控制延迟/传感器真实采样时刻。

每脉冲前100ms附近由实测姿态、髋角、轮角/轮速重构初态；非轮关节烘焙为刚性夹具，车身固定、双轮无接触。随后按记录请求零阶保持（每拍间维持上一指令），MuJoCo自由积分，不逐帧写回状态。小样本先用0.25ms积分完成链路检查；正式优化1ms步长、验证再用0.5ms复算。未来实测轮速改为1e8仍不改变预测，重复相同初态/输入逐位一致，排除了用实测状态冒充预测。

只改变左右轮armature（轮轴额外转动惯量）、damping（随速度增加的阻力）和frictionloss（干摩擦项）。零件质量/重心/刚体惯量、非轮参数、接触/驱动极性/零点/力矩换算不改，候选完整XML独立保存。
