# 当前r12与wheelleg_RL成功策略为何不同

2026-10-10，当前训练仓26_wheelleg，HEAD58947e8加已有r12改动。本轮仅对照源码、实际配置、检查点元数据和编译模型静态字段，没有改参数或启动训练。以当前r12为对象，避免沿用r9的初态结论。

## 结论

两边不是完整复现同一个实验。**最关键的已核实差异是成功策略的训练路径／初始化，以及编译后机器人动力学；当前奖励、模式和复位配置也不完全相同。** 普通PPO超参数一致不能消除这些差异。固定失败惩罚都为-4，因此这项不是两个工程之间的配置差异；它能解释本仓为何存在提前终止的激励，却不能单独解释参考成功而本仓失败。

此前“全部对齐”的说法应限定为当时移植范围；当前配置还保留了用户要求的动态模式、四腿两轮顺序及关闭膝奖励等改动，没有复现参考全部训练历史。

## 对比模型

参考当前最新仍为 `2026-10-08_18-01-01_recover_pose_v2_formal_headless_4096/model_1156.pt`，SHA256 `c2fd635796ab4cc7fcf0b096b05faf8cd308d3d74fad16dd1f963d7d20bd3c4c`。文件索引1156，检查点记录累计更新5163。

本仓为r12 `model_2999.pt`，SHA256 `43ec486322580d4a757da4e068932b2796706452360c7c301a22b9451b87f553`，累计更新3000，来源r11 model_999。完整路径、配置及当前编译字段见 [JSON](20261010-mjlab-r12-reference-comparison.json)。

本仓r9、r10、r11是分别从随机权重启动的实验，r12只接续r11，不能把其他实验的轮数累加到r12。

## 1. 训练历史／优化器起点不同

参考链条（当前检查点init_source／stage_history，以及其来源检查点和已保存历史核对）：

- v7：随机初始化、较宽5～10cm速度高度门控，50%普通／50%地面、混合速度命令；训练3000轮，先学到可靠低姿态站稳。
- v11：从v7加载actor、critic、Adam，收紧门控至3～6cm并加入膝限位惩罚-0.5，继续1000轮，累计4000；参考历史评估首次学会高度跟踪。
- v12混合：承接v11再训练500轮，累计4500。
- recover_ground_v1与recover_pose_v2：承接以上成功策略，转向零速／全地面恢复并增加机体扰动。当前累计5163。

本仓本次链条：

- r11：随机初始化；一开始即零速、3～6cm紧门控、膝限位奖励-0.5、动态模式；50%普通／50%地面，1000轮后仍低姿态、漂移、严格起立0。
- r12：从这一未学会起立的策略和Adam继续，关闭膝奖励，再训2000轮，累计3000；当前64个正式评估初态全部物理失败。

因此参考是在已有平衡／站高能力上强化恢复，本仓还在从无成功基础的策略中探索。参考的5150余轮并非全部使用当前recover参数，更不能把model_1156理解成只训练了1157轮。

更直接的旁证：参考工程自己的v9尝试从随机权重直接使用3～6cm紧门控，前400轮upright_fraction约0.16→0.04，第546轮中止；同工程从已有v7策略继续的v11成功。这是参考历史记录，本轮没有重新复测这些旧模型，也未证明门控是单一原因。见 [参考实验历史](/home/zn/文档/mjlab/wheelleg_RL/docs/ai/huananhu_experiment.md:58)。

## 2. 当前训练配方不相同

| 项目 | 参考当前recover | 本仓当前r12 |
|---|---|---|
| 模式观测 | 固定NORMAL | 动态normal/recover，含目标高和状态时间 |
| knee_limit软奖励 | -0.5 | 0 |
| 初态 | 100%地面 | 50%普通＋50%地面 |
| 地面机体扰动比例 | 50% | 0 |
| 动作／关节观测顺序 | 左腿、左轮、右腿、右轮 | 四腿在前、两轮在后 |
| 有效累计更新 | 5163 | 3000 |
| 当前阶段前是否已学会站高 | 是 | 否 |

其余26项奖励权重、控制dt=.02、腿PD60/2、速度高度门控3～6cm、当前高度命令27～34cm、零速命令和普通PPO算法参数已核对一致。失败权重均-200且启用dt缩放，单次终止项实际-4。

模式与膝奖励改变策略输入／目标；复位改变样本分布。动作顺序属于正确实现重排即可等价的接口差异，不能凭顺序不同认定接错电机。现有检查未发现错位驱动。

当前本仓复位更接近参考最早v7的50/50比例，但v7从零阶段的门控、速度命令和奖励加入顺序没有因此全部恢复；仅恢复初态比例不足以复现整个成功过程。

## 3. 机器人动力学不同

重新编译两侧当前MJCF，静态字段仍有以下差异（以下值是名义模型值，训练随机化会在其上叠加）：

| 参数 | 参考 | 本仓 |
|---|---:|---:|
| 主动腿关节armature | 0.015795 | 0 |
| 主动腿关节模型阻尼 | 0 | 0.03 |
| 被动腿关节模型阻尼 | 0.01 | 0.03 |
| 腿关节frictionloss | 0 | 0.015 |
| 轮模型阻尼／干摩擦 | 0／0 | 0.002／0.001 |
| 六个闭链connect的solref第一项 | 0.01 | 0.005 |

模型阻尼与控制器PD的D增益是不同字段。armature是关节附加惯量，会改变相同力矩下的加速度；solref影响约束响应。因此相同PD和PPO不能保证相同运动、接触和奖励分布。定义见 [MuJoCo armature](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-joint-armature)、[solver参数](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)。

两侧总质量当前均13.39458410046886kg。之前逐关节轴向／位置／限位、碰撞点云、复位库比较也没有发现几何或采样表差异，详见 [已有静态差异记录](20261010-mjlab-r9-reference-differences.json)。本轮未重复碰撞点云比较，不能把mesh文件哈希不同直接当作几何不同。

本仓solref=.005来自GPU闭链误差修复，不应为了追求文本一致直接恢复.01。惯量、摩擦等也应按机器人实际参数与闭链检查决定，不在本次解释中擅改。

## 4. 同样失败代价为何可形成不同策略

参考历史v10的零速低姿态奖励账本约+1.07/s；v11膝惩罚加入后约+0.2/s，仍正，已有站稳策略能持续获得收益。本仓r11 actor在当前r12奖励下名义诊断末10s每步reward约-0.07945，dt=.02，即约-3.97/s：低姿态、腿接地、漂移和消耗抵消了正奖励。

两组账本来自不同模型、初态和历史评估，不能当精确配对因果实验；它们说明相同系数并不保证相同实际回报。对于可持续赚分的行为，失败会切断收益；对于持续负分的坏行为，失败可以减少未来成本。

本仓不学习的32环境对照还验证：在相同r12奖励、逐项相同初始qpos和命令下，1000轮actor平均折扣回报-11.81、3000轮actor-9.24；后者平均0.90s物理失败。支持奖励与起立目标错位，但不能据此证明训练路径或某个物理参数各贡献多少。见 [退化分析](20261010-mjlab-r12-degradation.md)。

## 合理的后续方向（未实施）

先把参考成功策略的分阶段训练流程在本机器人上复现，并明确保留哪些用户指定接口；核对附加惯量／阻尼／摩擦等是否应匹配真实电机与机构。随后在相同模型、相同训练起点下每次只改变一个因素并用严格起立／存活／站稳评估。

现有证据能确认“不是同一实验”及几个机制，不足以给各因素分配因果比例。本次未重新训练、未修改奖励或机器人参数。
