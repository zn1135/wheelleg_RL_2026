# H7 下位机、观测与输出验证——对话总结

整理日期：2026-10-01。本文汇总本次对话的需求、改动、实测证据、用户决定和续接位置；不是逐字聊天记录。

**当前结论：完整 25 维观测的数据构造与真实策略动作回填／历史时序已有验证；IMU 三轴、腿侧来源、慢速髋角方向及左右轮主动前进方向已有实测依据。但精密零点、部分膝角、轮速比例、四腿非零输出和完整策略闭环仍未全部验收，不能概括为“所有观测和控制都正确”。**

## 1. 原始需求与范围演进

用户最初要求将 `~/文档/H7_clion` 设为新的下位机代码路径，写入配置，继续用 VOFA 串口发送并验证观测数据。

1. VOFA 接收和观测数值复算。

3. 左右轮来源、转向及圈数积分。
4. 腿关节来源、方向、零位姿态与虚拟膝一致性。
5. 遥控使能／失能和掉线保护。
6. 真实策略推理下的上一拍动作、5 帧历史和 100 Hz 通信时序。
7. 动作到虚拟 PD 的离线复算。
8. 左右轮单独主动小力矩测试。

用户提供的照片只用于记录机械参考姿态；没有从照片中推算精密角度或把图片内容当成操作指令。

## 3. 必须保留的用户决定

- **跳过轮速减速比校准**：保留配置 **15.5**，不因手转圈数误差自行修改，也不把它标为已校准。
- **不再补做左膝手动屈伸**：明确左膝动态仍未验收，不能重复要求此前已取消的动作。
- 零位参考是**电机调试软件原始位置为 0、机身平放、双腿后摆**，不是下位机加偏置后的角度为 0。
- 用户提供的“后 33、下 10”单位最终确认为厘米，即轮轴相对髋轴约**向后 330 mm、向下 100 mm**。随后用户澄清该尺寸来自 SolidWorks 测量图，不是实物零位的独立量尺结果；原图的姿态和测点仍待核对。
- “轮子接地、按压机身”那段，用户后来明确**没有做动作**；不能记为已经尝试但失败，也不能当成膝不响应。
- 遥控使能沿用旧 USB 调试档位：**先左下，再左上＋右下**。
- 主动轮测试先尝试 0.05、0.10 N·m；用户反馈均没有可见运动，随后明确要求 **0.5 N·m**。

## 4. 25 维观测与接口约定

本次机器人为 chuanliantui，大轮腿；机体系 **+X 前、+Y 左、+Z 上**。不能套用 imcawl 的 +Y 前向约定。

| 观测索引（从 0 开始） | 内容 | 缩放 |
| --- | --- | --- |
| 0–2 | 机体系三轴角速度 | ×0.25 |
| 3–5 | 机体系重力投影 | 不缩放 |
| 6–8 | 前向速度、偏航角速度、目标高度命令 | ×[2, 0.25, 5] |
| 9–12 | `[lf0, lf1, rf0, rf1]` 相对默认角的位置 | ×1 |
| 13–18 | `[lf0, lf1, lfwheel, rf0, rf1, rfwheel]` 速度 | ×0.05 |
| 19–24 | 上一拍策略原始动作 | 不乘位置／速度控制尺度 |

连续轮的绝对位置不进入 actor。历史为 **25×5=125**，最旧帧在前、当前帧在末；100 Hz 时相邻 5 帧首尾跨度为 **40 ms**。
默认关节角为 `[-0.06, 0.10, 0, 0.06, -0.10, 0]`，动作与观测整体裁剪范围均为 ±100。

VOFA 使用 UART8、1152000 baud、JustFloat；普通预览为 63 路约 25 Hz，前 25 路是完整观测。
布局标识普通预览为 2501，策略诊断为 2701；不能把 25 Hz VOFA 输出频率和 100 Hz USB 策略诊断混为一谈。

`numeric_valid=1` 只说明来源在线、几何可解和浮点数有效。整体物理验收标记 **`LOWER_OBS_MAPPING_VERIFIED=0` 保持不变**。

## 5. IMU：已修正并完成三轴动态方向验收

原映射存在 XY 轴及符号问题。最终陀螺仪和四元数向量部分使用：

```text
src  = [1, 0, 2]
sign = [-1, +1, +1]
```

角速度换算到 rad/s，再乘观测尺度 0.25。用户通过明确物理动作核对方向：

| 动作 | 主响应轴 | 实测摘要 |
| --- | --- | --- |
| 向前低头，再回水平 | Y 正、Y 负 | 主段积分约 +26.90°／−28.32°，与四元数相对转角接近 |
| 机器人自身右侧降低，再回水平 | X 正、X 负 | 主段约 +25.98°／−25.48° |
| 俯视向左逆时针转，再转回 | Z 正、Z 负 | 主段约 +97.59°／−99.07°；用户确认实际接近 90° |

结论是方向及内部数值自洽，不是独立精密角速度标定，也不验收高频采样延迟。
横滚记录静止准备阶段有一次 200 ms 间隔，没有将该间隔用于动作积分，也未声称整段无缺口。

俯仰最初的解析错误是 PC 采集器把载荷内部偶然拼成的 JustFloat 帧尾误当成分帧边界。
已改为已知帧长优先并校验布局，原始字节无损重解码；原报告和原始数据均保留，没有将其误判为真实串口丢字节。

详见 IMU 动态验证：`$H7_REPO_PATH/docs/imu-dynamic-validation.md`。

## 6. 轮速与腿观测：来源已确认，标定保留边界

模型名称与物理左右容易混淆，最终映射为：

| 物理位置 | 模型侧 | 驱动来源 | USB 轮命令／反馈 |
| --- | --- | --- | --- |
| 自身右腿／右轮 | lf，位于 −Y | DM2/3；DJI0、CAN201 | 命令索引5／wheel反馈索引1 |
| 自身左腿／左轮 | rf，位于 +Y | DM0/1；DJI1、CAN202 | 命令索引4／wheel反馈索引0 |

轮观测移除了错误的 USB 逻辑左右交换，直接取 DJI 槽0/1，再按模型 lf−、rf+ 换算。
腿观测修正为 DM2/3→lf、DM0/1→rf。**不能把观测来源的修正直接套到旧 USB 力矩接口上**，后者的轮命令和轮反馈交换是配对的。

手动轮验证中：用户确认向前 3 圈，积分约右 3.47 圈、左 2.90 圈；用户指出可能存在操作误差。
右轮精确一圈补测中，编码器和速度积分相互接近，但配置 15.5 换算后仍约 1.13 圈。
用户随后要求跳过减速比，故保持 15.5，仅保留方向、来源和相对一致性结论。

左右腿单独摆动及修正版复测确认了侧归属和慢速髋方向：右腿前摆 lf0 增大，左腿前摆 rf0 减小。
四路电机速度与位置差分相关约 0.996–0.998，拟合比例约 0.991–1.008。
静止 DM 速度约 ±0.01099 rad/s 是速度量化值，不能把其长时间积分直接解释成位置漂移。

详见 轮速验证：`$H7_REPO_PATH/docs/wheel-speed-validation.md`、腿观测验证：`$H7_REPO_PATH/docs/leg-observation-validation.md`。

## 7. 零位与虚拟膝：没有发现厘米级粗测下的大偏差，但未完成精密验收

用户指定原始零位姿态后进行了 5 秒只读采集，没有重设编码器或修改偏置。

虚拟膝由前后两个输入角及 CAD 闭链解算，不能把后电机位置直接当膝角。

- 该姿态模型预测右轮轴约后 320.5 mm、下 109.1 mm，用户粗测约后 330 mm、下 100 mm。
  约 13 mm 的端点差只支持姿态方向和量级合理，不能用于精密调零。

- 右膝混合屈伸中，位置／速度内部一致性良好，但候选膝角峰值约 0.915 rad，高于训练上限 0.77 rad。
  操作包含抬轮端及轮接地按机身，不能宣称纯膝或单电机隔离试验通过。
- 没有因此擅自调整零点或扩大训练关节限位。
- 竖直长连杆参考步骤已被用户零位方案替代；明确左膝补测已被用户取消。

## 8. 遥控使能／失能

参考旧 H7 实现接入 DR16：UART9、PD14 RX、100000 baud、8E1，使用独立 DMA 缓冲及接收事件。

- 上电失能；必须先观察到左下，再左上＋右下才允许一次使能。
- 板载 USB、CAN 和六台电机就绪后进入**零力矩待机**，不执行策略、不保持姿态。
- 第一条合法 SET_TORQUE 后启用 100 ms 指令看门狗；重复 ARM 不刷新它。
- 左拨杆离开上档、右拨杆离开下档、遥控 50 ms 掉线／坏帧、USB 断开、STOP 或故障均撤销使能。
- 停机后持续保持上档不会自行重启，需重新左下再上。

板测确认：双下失能、左上右下四 DM 零力矩使能、回双下失能；关遥控失能，恢复连接且继续保持使能档也不会自动重启。
遥控门禁板测期间目标力矩全为 0。软件 50／100 ms 阈值不能直接当作已测得的机械停机延迟。

详见 遥控说明：`$H7_REPO_PATH/docs/remote-enable.md`及 `captures/20261001-remote-enable-firmware/`。

## 9. 真实策略动作回填与历史时序

使用完整 checkpoint：

```text
logs/chuanliantui_standup/Sep22_16-26-11_standup_no_legangle_resume/model_6000.pt
SHA256: 8070977e19114cb9bbf358a090bd78cdbd1be568a76e02d417c369e828bc8f36
```

模型为 encoder 125→128→64→3，actor 28→128→64→32→6。实际推理运行在**电脑 CPU**，不是 H7 板上网络。
没有使用缺 encoder 的 `policy_1.pt`。

2701 诊断由 H7 构造观测和历史，电脑回传六维原始动作，下一拍回填到 obs[19:25]；全程禁止电机使能及力矩执行。
会话 session、source_seq、重复／漏发／迟到、非有限数和发送背压均检查。

| 采集 | 结果 |
| --- | --- |
| normal-02 | 1001 帧，全部10 ms；last_action和125维history逐位一致 |
| drop-01 | 故意漏发第120拍ACTION，下一10 ms边界进入预期 DEADLINE FAULT |
| reset-01 | 新会话1001帧；首帧last_action清零，首帧重复5次初始化history |

正常两段共 2002 帧，动作接受延迟最大 4 ms；在线推理含转换中位约 0.40–0.42 ms、最大约 0.845 ms。
每段结束均确认 OFF、DM 失能、六路目标为 0。会话重启复测不应表述成必然进行了物理断电复位。

第一次 normal-01 因主机错误要求 START 回应时尚无 sample0 而退出，后修正为允许合法的“未采样／已准备首帧”两种时序；只修改主机，未重复刷固件。
训练与部署在饱和历史、reset动作边界的既有差异仍记录在接口文档，没有顺手修改训练实现。

**通过的是策略原始动作回填和历史通信，不是六电机实际执行策略的反馈。**
详见 策略时序验收：`$H7_REPO_PATH/docs/policy-runtime-validation.md`。

## 10. 动作到力矩的离线复算与映射审计

名义控制：腿位置目标 `default + 0.5a`、Kp/Kd=10/1；轮速度目标 `10a`、Kp/Kd=0/0.1。
虚拟力矩限幅 `[40,40,3.9,40,40,3.9]`，策略100 Hz、目标执行内环500 Hz。

用上述2002帧观测及各自产生的发布动作复算假想首个PD步，发现双轮每帧达到各自±3.9 N·m限幅，腿虚拟力矩最高约35.7 N·m。
这反映失能静止条件下的计算输出，不证明观测错误、策略闭环失稳或真实电机受到了这些力矩。
2701帧没有同拍四个DM输入角，因此没有从异步STATUS拼出“精确同拍实体力矩”。

设当前 CAD Jacobian 为 `[J前,J后]`，与现有观测速度配对的虚功映射是：

```text
USB0 =   τ_rf0 + J_rf前 * τ_rf1
USB1 =           J_rf后 * τ_rf1
USB2 = -(τ_lf0 + J_lf前 * τ_lf1)
USB3 =          -J_lf后 * τ_lf1
USB4 =  τ_rfwheel
USB5 = -τ_lfwheel
```

驱动已经在边界施加命令／反馈极性，不能再重复叠加 raw 极性。
旧 H7 的 Jacobian 顺序及机构语义不同，不能直接复制。上述公式尚未接入完整策略执行链；物理腿映射也未因代数配对而完成验收。

详见 动作输出审计：`$H7_REPO_PATH/docs/action-output-validation.md`。

## 11. 主动轮测试最终结果

用户确认台架准备好后，只对单轮施加脉冲，四腿和另一轮指令始终为0；遥控负责新鲜使能，工具不发ARM。

| --- | ---: | --- | --- |
| 右轮0.05方案 | 0.05 N·m | 约300 ms正常结束 | 完全没动；有电流响应，方向未判定 |
| 右轮0.10方案 | 0.10 N·m | 约300 ms正常结束 | 仍完全没动；有电流响应，方向未判定 |
| 右轮0.50方案 | 0.50 N·m | 约102 ms，速度越阈停止 | 自身右轮、胎顶朝机头；方向通过 |
| 左轮首次0.50方案 | 未发SET | 零输出等待阶段超时 | 没有动作，不能作为左轮响应证据 |

主机已将零力矩等待改为20 Hz、40 ms查询预算；脉冲前重新做10 ms内的就绪检查，并限制首SET有效期。
实际输出仍100 Hz、严格10 ms回复截止、最多300 ms；最后24项相关模拟检查通过。

本次确认的是两轮主动通道与前进方向，不是轮速比例或力矩幅值标定，也没有执行完整策略。
详见 轮输出完整报告：`$H7_REPO_PATH/docs/wheel-output-validation.md`。

## 12. 权限、烧录与遇到的问题

VOFA+曾占用串口；用户退出后才继续采集，没有抢读现有连接。
USB权限曾多次需要 `sudo chown zn /dev/ttyACM1`，原因是烧录／复位后USB重新枚举，临时设备所有者设置丢失；不是每次采集都需要设置。
曾尝试setfacl，但实际输入连续缺少`:rw`，改用chown；没有安装持久udev权限规则。
后期策略主机修复和单轮工具改动都不需要重新烧录，因此没有继续要求用户改权限。

无线烧录器曾出现SWD读失败；用户重插后，以下保守传输参数完成烧录和逐字节Flash读回：

```text
pyocd: -t stm32h723xx -f 100k
-O cmsis_dap.limit_packets=true
-O cmsis_dap.deferred_transfers=false
```

不能只看pyOCD退出码，要同时检查读回文件长度、逐字节一致和内核运行状态。
