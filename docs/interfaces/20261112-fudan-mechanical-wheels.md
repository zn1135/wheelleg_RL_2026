# 复旦轮端机械候选：惯量、阻尼、摩擦替代出力曲线与0.45

用户2026-11-12要求用惯量等参数替代轮端曲线和0.45。当前复旦训练及MuJoCo Warp GPU默认选择`FudanWalkCfg.sim.wheel_model='mechanical'`；旧方案可显式选择`legacy_curve`。只修改训练侧，H7代码/PD/固件未变，部署负责人核对待确认。旧模型、日志和已提交的交付包保持原样；没有新训练或Git操作。

## 控制和物理定义

机械候选链路：PD与原强度随机化 → 原±3.9名义Nm请求限矩 → 单位增益执行器 → 原生关节惯量/阻尼/摩擦参与动力学。执行器G=1，不调用原轮速衰减曲线，不再施加额外0.45。机械模式拒绝同时配置额外轮增益、响应延迟/滞后或额外轮轴上限；原策略动作/传感延迟仍按原配置执行。

参数唯一源为`resources/robots/chuanliantui_new_1/mjlab/wheel_mechanical.json`，顺序固定左lfwheel、右rfwheel。新创建环境从该文件读取；这是等效机械候选参数，不是测得的轴端物理真值。

- `envs/fudan_ppo_walk/wheel_physics.py`在复旦自己的MjSpec内设置机械轮参数和固定单位增益；共享XML保留历史轮曲线，其他任务不切换物理。
- `HuananhuPdAction`仅在模型包含非零速度曲线指数时计算原曲线；机械模型直接提交限矩后的请求。`WheelMotorResponse`在机械模式保持中性并拒绝追加缩放。
- 初态夹具保存实际关节阻尼/摩擦和执行器增益，参数差异进入cohort；不能把新旧物理当成同条件的策略比较。新PT保存`physical_wheel_model`，训练快照包含参数JSON。
- Actor25/历史125/Critic141+3/动作6、history v2/v3语义和2ms物理/PD、10ms策略不变，无ONNX/H7接口形状变更。本次只有旧17679冻结推理，没有新权重。
- 旧诊断工具默认明确选`legacy_curve`，旧参数探针仍从历史曲线开始再记录候选覆盖；新正式验证用`--wheel-model mechanical --wheel-motor-gain 1`。旧训练启动器的源码/配方一致性检查会拒绝未声明的新物理，不能直接重复旧预算命令。

## 验证与限制

21项机械控制/物理检查通过：仅轮端物理改变、单位增益、拒绝0.45、正反转及±100rad/s下的实际执行器力矩、复位和20环境500积分拍有限性。15组请求/速度组合的实际力矩最大误差2.39e−7Nm；旧曲线17项回归检查也通过。MuJoCo3.11的关节damping是三分量存储，本候选仅设置线性分量，其余为0。

有限候选扫描63条30秒GPU轨迹后，选定上述组合；正式机械实现另采集18停车/外扰与3零指令，旧路径新录3零指令并复用已存18停车，形成42条最终对照。21组相同初态/PD/命令与随机条件逐数组核对，物理参数差异明确记录。无外扰仍2/9、外扰仍0/9、30秒零指令仍1/3，原通过样本集合保持；不是完整987、转向/变高/起立或真机验收通过。

最终零指令腿摆（末1秒）旧→机械：0.22m为5.62→5.37°，0.26m为2.36→2.06°，0.30m为0.19→0.16°。现象接近是对旧已接近实机方案的间接对照，不能当成实机参数辨识。

历史3Nm/300ms悬空脉冲做简化单转子CPU诊断（最终整机验证仍为GPU）：原曲线、曲线×0.45、机械候选的历史验证分组轮速RMSE分别2.84、6.78、9.39rad/s。机械候选在该高出力响应上更差；只靠恒定惯量/阻尼/摩擦不能保证同时复现原转速出力限制和滑行响应。该历史数据曾参与此前模型选择，不是新的独立盲验证；简化诊断忽略小重力矩及实际支撑姿态，也不覆盖接地负载和低指令标定。

因此此替代保持为机械候选，不能称全工况真实电机模型。下一步优先验证低速前后运动、刹停及不同指令幅值下的轮速响应，再决定是否用它重训；没有用户新预算不启动训练。[完整数据、视频及命令](../../artifacts/real2sim/wheel-mechanical-replacement-20261112-01/README.md)。
