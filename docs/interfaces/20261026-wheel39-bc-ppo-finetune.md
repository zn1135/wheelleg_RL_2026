## 新模式的实际变化

| 项目 | 新模式 |
|---|---|
| 动作探索标准差 | `[.001,.001,.005,.001,.001,.005]`，固定；腿0.001、轮0.005 |
| 物理／电机参数 | 名义参数，关闭质量／摩擦／增益／弹簧／偏置随机化和推扰 |
| 观测 | 关闭观测噪声和传感延迟；动作延迟仍独立随机2／4ms |
| 数值计算 | 网络FP32，关闭TF32，减小小标准差下批量计算误差的影响 |
| 前20轮 | 只更新价值网络，每轮仍是24步采样、5×4个小批次；计入总轮数预算 |
| 后续更新 | 动作网络学习率0.000001，价值网络0.0001；固定学习率，熵系数0 |
| BC保留 | 冻结原BC的动作均值网络；在当前采样状态上惩罚偏离BC的动作，按固定动作标准差归一化，系数1 |
| PPO单轮变化 | 小批次与本轮采样策略的KL距离超过0.01时，余下小批次只更新价值网络 |
| SMP | 同一冻结先验、单位误差尺度、默认权重1，不重训、不在线更新尺度 |

KL是衡量两套动作分布差多远的数值；阈值在小批次更新前检查，不保证更新后的距离永远小于阈值。BC约束是软约束，未保证新训练后一定保住40/40，必须实际复测。固定参考只覆盖当前采样的状态，没有另加离线示范重放约束。

`finetune.py`的`ProtectedPPO`使用当前安装rsl_rl的MLP PPO接口实现此限定更新，不修改外部依赖。检查点内保存完整冻结参考、固定配方、已完成轮数和actor／critic实际更新计数；恢复不用再次读取BC文件，且不能重新开始20轮预热。原BC仅用于新运行初始化。

## 停车奖励

原`zero_command_hold`权重3，是速度指数分数与位置指数分数相乘。新模式将其替换为两个独立项，其他任务奖励不变：

- `zero_command_brake`权重2：`1/(1+(平面速度/0.05)^2)`。
- `zero_command_position`权重1：`1/(1+(锚点距离/0.1)^2)`。

两项仍需零速、非恢复／非腾空／非跳跃、姿态正常且稳定0.5秒；只有位置项要求锚点有效。锚点锁定逻辑没有改。两项最大和仍为3，由奖励管理器统一乘一次0.01秒。较远的锚点不再把减速奖励乘成零，连续减速能持续得到正向差异；不放宽原停车验收阈值。
