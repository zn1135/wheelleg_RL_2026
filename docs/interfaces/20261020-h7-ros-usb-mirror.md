## 接口与兼容性

- H7板载USB接Jetson USB口，固定发送48个小端float32及JustFloat尾，共196字节；约100Hz尝试。序号、快照毫秒、CRC16/CCITT-FALSE、来源有效位和发布年龄保持；32～38槽改为0，不支持USB探测回报或控制命令。
- USB未枚举、发送忙或提交失败立即跳过；复制前检查空闲，异步传输完成前不覆盖静态帧缓冲；重连后发送最新快照。普通用户UART探测接收代码保留，但USB镜像不返回其状态。
- 线上四髋仍为公共驱动的连续标定角及速度；双轮为轮轴累计角及速度；IMU为公共wxyz四元数与机体系角速度。Jetson从本固件的`machine_config.c`读取原有motor_sign／motor_zero，再映射一次到模型；不重复公共驱动标定和轮减速比换算。
- 策略观测39／动作6、动作历史、控制频率、默认角、极性、零点、IMU轴向、PD、限幅、模式许可、模型生成文件均保持原实现；不需要重训或重新导出。本次没有新模型交付，模型历史说明见[model5849说明](../onnx-huananhu-multimode-model5849.md)。
- Jetson复用闭链运动学求解，机身平移固定并标记未测量；200ms无新帧显示STALE、冻结姿态。用户随后确认趴地并选择超模型范围仍显示：闭链闭合的越界解继续更新，腿部黄色显示MODEL RANGE WARNING；闭合失败或反馈无效仍冻结。XML限位、H7控制与物理标定不变。镜像不运行策略或物理步进，旧双向UART探测程序不能作为USB验收工具。

## real2sim录制与离线诊断

用户接受当前趴地镜像效果，左膝超过XML上限约7°、右膝低于下限约4°作为已知差异保留；暂不修改XML或标定。数值表示模型超限量，不是已测得的实机角度误差；差异原因及完整机械行程仍待台架。当前阶段先保存实机反馈、离线重现并检查数据与运动学差异。

现有接收入口增加三种用法，原直播与`--report`继续可用：

```bash
# Jetson项目根目录；先退出占用同一USB的旧镜像程序。
# 同一接收线程显示并录制30秒，每次使用不存在的新会话目录。
.venv/bin/python sim2sim/real2sim_huananhu.py \
  --port /dev/serial/by-id/替换为实际H7设备名 \
  --machine-config deployment/H7_RL_ros/imcalib/config/machine_config.c \
  --seconds 30 --record artifacts/real2sim-新会话名

# Jetson项目根目录；离线原速回放，不连接USB。
.venv/bin/python sim2sim/real2sim_huananhu.py \
  --replay artifacts/real2sim-新会话名

# 将完整会话复制到训练仓后，在训练仓根目录分析。
mjlab_training/.venv/bin/python sim2sim/real2sim_huananhu.py \
  --analyze artifacts/real2sim-新会话名
```

录制右上角显示用时／剩余时间（不限时为`manual stop`）、RX帧数、原始流MiB、待写事件、`SAVE`目录和错误／结束操作；终端每秒输出`{"recording": ...}`。结束后看`status=SAVED`与完整绝对路径，并等命令正常返回；若为`ERROR`，不能将会话当作已完整保存。

`meta.json`记录采集所用模型／机器配置的项目相对路径及SHA256、完整或错误结束状态；`stream.jsonl`记录原始USB收包字节、相对主机单调时间ns及连接事件。离线入口从会话选取模型和机器配置并校验哈希；文件位于另一位置时可显式传`--model`或`--machine-config`，仍要求同哈希，不能换配置后把回放当作原始结果。

回放复用同一解析器、序号／时间处理与闭链解算，保留断流200ms过期和范围越界黄色警告；不加载策略、不做物理步进。分析生成会话`analysis/trajectory.csv`、`report.json`和`signals.png`，记录接收质量、有效来源、模型姿态、派生腿长／腿角、闭合残差和越界。Matplotlib仅使用训练仓本机已有mjlab环境，Jetson基础依赖不增加绘图库。直播／录制／回放无需Matplotlib；完整软件检查会调用分析，使用训练仓mjlab环境执行，不要求部署到Jetson。

当前帧没有实际obs39、RC命令、策略动作、最终下发力矩、机身世界平移或接触真值；镜像腿长也来自同一份关节反馈，不能作为独立实测标定证据。本轮结果只用于数据链与运动学差异，不能据此量化质量、摩擦、力矩响应或完整动力学差异。H7、XML、物理标定及`H7_RL`主工程保持原样，无烧录、训练、提交或推送。

## 离线MuJoCo动力学对照

`sim2sim/real2sim_dynamics_huananhu.py` 将台架实测输入送入 MuJoCo，再用同一实录动作对原模型与候选模型做整机短窗预测。运行在本机 mjlab 环境，不连接 USB，不重新推理策略、不修改 H7、正式 XML 或机器标定。它从原始会话重新解析，核对流、XML、机器配置哈希，不依赖旧分析 CSV 或 `artifacts/` 中的临时脚本。

```bash

  --bench-session <包含meta.json和stream.jsonl的脉冲会话> \

  --machine-config deployment/H7_RL_ros/imcalib/config/machine_config.c \
  --out artifacts/<新对照目录>
```

默认每 10ms 的有效起点均做 10／20／50／100ms 预测；`--rl-stride N` 可每 N 个有效起点取一个，并明确报告覆盖数量。输出目录必须不存在；失败保留 `run.json` 的未完成标志。运行不写入源会话，历史结果保持独立。

- 台架先用实测关节重构闭链，再把机身和非轮姿态固定；只保留双轮转动和原轮部件质量／几何，无地面接触。实测膝越界量单独报告，固定台架不保留相互冲突的闭链和关节限位，正式模型限位保持。每段仅初始化一次轮角／速度，随后 `mj_step` 自行预测；固定台架与单轮方程数学等价，整机部分另外保留完整自由度与接触。
- 请求力矩为主输入口径，按固件原刻度换算的电流为第二口径；后者仍不是独立轴矩测量。分别处理请求采样边沿和电流关断证据，原模型／候选在同一场景始终得到相同输入；不根据候选预测轮速重新触发撤销，不用留出轨迹反拟合每次延迟。电流场景另检查 ±5ms 采样平移；请求的开启与关断边沿独立取区间四角，关断区间包含组间电流差异证据。
- 每个轮向第一次重复拟合、第二次留出，再交换拆分。左右各拟合附加惯量、阻尼、干摩擦；同轮正反共用参数。用多个初值及剖面敏感性检查参数是否能分开；不把局部拟合协方差解释成物理置信区间。附加惯量范围 0～0.012kg·m²、阻尼 0～0.03Nm·s/rad、干摩擦 0～0.5Nm 只是本次优化边界。
- `candidate.xml` 从正式模型单独生成，只增加两个轮关节的三个参数，网格引用仍指向原资产；编译后逐项核对质量、惯量、关节、闭链、几何和执行器字段。台架固定约束不能进入完整候选。机身自由时，关节附加惯量与轮本体惯量的耦合不同；该候选不得自动当作物理标定使用。

`bench-report.json`／`bench-predictions.csv`／`bench-states.npz` 保存参数拆分、边沿敏感性及台架完整自由预测；`rl-report.json`／`rl-predictions.csv`／`rl-states.npz` 保存窗口初态、拒绝原因、分时长误差和整机完整状态。`bench-comparison.png` 保留原模型曲线，`bench-detail.png` 看候选与实测细节，`input-timing.png` 看输入时序，`rl-comparison.png` 看短窗误差。`report.json` 是完成与限制的总入口，`source/` 保留实际运行源码。
