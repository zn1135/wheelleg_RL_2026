## 测点与配对

全部绝对时间使用原 `Mono_Ns_Get()`；策略、控制拍、缓存和CAN尝试分别编号，动作重置用 `reset_count` 隔离。数值和对应原接收时间在同一份反馈快照中复制，不用后来的IRQ时间配旧数值。

| 记录 | 内容 |
|---|---|
| SAMPLE | 实际反馈快照→500Hz模型缓存；IMU、四髋、双轮、遥控的原接收数据龄，未知为UINT32_MAX |
| POLICY | 策略任务入口、观测读取偏移/构造耗时、成功SDK调用耗时、动作发布；关联真正读取的缓存；未选择/坏观测/SDK失败/跨重置丢弃分别记录 |
| PD | 求解起止、同拍六电机反馈数据龄、实际动作序号及动作年龄；首次有效PD消费另有标志 |
| ACTUATION | 每次实际入口/结束、TIM6最近触发序号及入口年龄、分发编号/策略/故障/阶段；正常不分发间隔拍也记录 |
| CAN | 原8字节报文、总线、硬件buffer、提交起止、完成IRQ/复用前轮询观测、HAL失败/停止未完成；分发上下文仅对原任务有效 |

解码得到：来源到策略读取、来源到PD、缓存到发布、发布到首次PD、后续PD动作年龄、连续区间内已观察同动作保持时间/复用拍数、任务入口间隔/触发推进数，以及逐总线/CAN ID的入队调用和完成观测耗时。按类型、结果、可追溯模式/故障/阶段分组；无法配对留空，不跨缺号/断连/重置补出延迟。

来源年龄按微秒向下取整，构造/SDK耗时为整数微秒，读取偏移为整数纳秒；无纳秒准确度承诺。SDK失败或未执行时不沿用旧 `run_us`。首次PD消费只证明动作被计算使用，不证明最终出力许可通过。正常约20ms动作保持已经由现有50Hz策略体现，不能再额外加一笔20ms到仿真。触发一次推进多拍也不单独证明丢了同样多拍，须结合入口间隔、积压和动作年龄判断。

CAN不改CubeMX配置或Tx事件FIFO，只启用已有TX buffer完成通知，分别保存每条总线32个buffer的原提交。旧IRQ未处理就复用时记录轮询观测；停止/无法确认成功明确标记。**IRQ/轮询时间是发送完成观测上界，含软件响应，不等于精确电气发送终点、目标电机收到或力矩生效。** 同IRQ多个完成不能推断物理次序。

## 线上布局、开销与兼容性

独立魔数 `H7LAT001`，全部小端。40B头为 `8s,4H,6I`：version=1、record_size=64、count≤128、reserved=0；后六个uint32依次为packet序号、记录尝试序号、丢弃数、打包前积压、高水位、尚未导出完成事件的CAN pending数。尾部CRC16/CCITT-FALSE覆盖头和记录。

| 字节偏移 | 字段 |
|---:|---|
| 0 | uint32全局尝试序号 |
| 4/6/7 | uint16 kind、uint8 source、uint8 flags |
| 8/16 | uint64 begin_ns / end_ns |
| 24/28 | uint32 correlation / reset_count |
| 32 | uint32 value[8]；逐kind定义以 `latency_capture.h` 为准 |

时序队列1024×64B，最多128项/批；与644B镜像及最多48项输出记录合并，最大13144B（首版为24项/11032B）。原异步缓冲在发送完成前不覆盖，USB忙/失败时两队列均不出队；队满只丢记录并累加序号/计数，不等待或改输出请求。首尾排队数、CAN pending、CRC、缺号与重连分别报告，不能把未导出尾部称为已测完。

增加记录复制、完成IRQ、CRC和USB负载；**尚未板端证明不影响500Hz/50Hz调度或持续吞吐**。没有新增任务/控制收包、改变CAN报文/速率/仲裁配置、提高优先级或改变许可门控。

观测39/动作6、缩放/顺序/上一动作语义、映射/初态/恢复/停机、PD/限幅、标定、策略和XML保持，名义频率不变；不需重训/重导出，本轮不改仿真延迟。原记录器仍完整保存原始字节，无需加写指令；旧解析器继续读取原644B前缀/H7OUT001。主UART工程不同步。新解码器遇旧固件明确拒绝，不回填新指标。

固件代码和解码已准备，GCC候选已构建；**未烧录**。H7负责人、板端数值/开销/吞吐和行为均待确认；预期manifest不是板端启动身份证明。
