## 电机响应候选（未实测，默认关闭）

作者另行选择先给仿真增加可调响应模型。训练/play与CPU回放共同读取`h7_timing.json`中`simulation.motor_response_time_constant_s`，单位秒，默认`0.0`表示直接使用原PD请求。正值启用六电机共用的一阶名义力矩响应：PD目标力矩变化后，执行输入逐步跟随；该参数是时间常数，并非固定等待后突然生效的延迟。模型类型为`first_order_nominal_torque`，校准状态为`unmeasured`。目前没有依据给六电机指定真实时间常数或分别拟合。

位置：动作FIFO → 原PD/强度/限幅 → 响应状态 → 原轮端速度增益 → 物理步进。每2ms子步，`alpha = 1 - exp(-dt/tau)`，`response += alpha * (request - response)`；得到的离散响应值供本子步积分使用。这是2ms网格下的近似，不是连续电流环仿真，不能解析微秒级响应。`tau=0`单独旁路，逐值保持原输入。时间常数越大，跟随越慢；正常恒定输入趋近原目标。原2ms动作等待仍独立保留；未额外假定CAN传输死区时间。

复位清除本环境响应状态，部分复位不影响其它环境；趴地禁用门控立即清零响应，不引入残余出力。训练`torques`与CPU `step()`返回值仍为原名义PD请求，实际执行输入在`_motor_response_torque`，之后轮端仍经过原等效增益。因此候选状态不能当作已测轴端力矩或真实电流，也不改变现有诊断字段语义。

修改共享JSON的时间常数后，重新创建训练/play环境或CPU回放才生效。CPU程序接口另可用`Playback(motor_response_time_constant_s=...)`覆盖，并在回放报告时序配置中保存有效值。`0.004`只用于检查一阶模型，不是推荐或实测参数；没有自动启用或启动训练。39/82/6接口保持，非零候选值下的起立/平衡/跟踪与实机匹配尚未验收；H7部署负责人核对待确认。
