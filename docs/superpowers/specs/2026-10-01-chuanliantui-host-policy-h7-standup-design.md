# 串联腿电脑推理、H7 执行动作的地面起立设计

日期：2026-10-01。目标机器人为 chuanliantui 大轮腿，训练仓工作分支为
`26_wheelleg`，设计时 HEAD 为 `bb56dd40964dc569b4e2a406983b03fa19d943a1`。
训练仓与 `$H7_REPO_PATH` 均有既有工作成果；后者没有 Git 元数据。
实现时沿用当前工作区，不切分支或创建 worktree，不覆盖现有采集与模型。

## 目标与成功条件

电脑运行包含 encoder 和 actor 的完整
`logs/chuanliantui_standup/Sep22_16-26-11_standup_no_legangle_resume/model_6000.pt`
（已记录 SHA-256：`8070977e19114cb9bbf358a090bd78cdbd1be568a76e02d417c369e828bc8f36`），
H7 从真实反馈构造 25 维观测和
125 维历史，按 100 Hz 交换观测和六维原始动作，在板端以 500 Hz 完成
虚拟关节 PD、闭链力矩变换以及四台 DM、两台 DJI 的输出。首次整机试验从
0.15 m 左右的地面后摆姿态开始，命令为 `vx=0`、`yaw_rate=0`、目标高度
`0.20 m`。现场人员确认轮接地并经电脑发送一次接管指令；接管前执行零策略
动作，接管后的下一完整策略步开始使用 actor 动作。

一次试验只有在现场观察到机身起立并维持直立、轮着地且未发生保护故障，
同时记录显示策略/PD 周期、输入输出、遥控状态和停机均符合本设计时，才称
为“地面起立闭环通过”。机身高度应达到至少 `0.18 m` 并维持至少 `0.5 s`，
与训练任务的高度和持续时间门槛对应；现场需提供可靠的高度观测，不能从
现有 H7 遥测凭空推断。行走不在首轮验收范围，起立稳定后另设速度命令试验。

## 已有证据与未闭合差异

- 2701 失能诊断已验证同一个 checkpoint 在电脑 CPU 推理、100 Hz 观测/历史、
  动作回填和漏拍故障；它与电机使能互斥，不能直接变成执行模式。
- 双轮的主动输出槽位及前进方向已有单轮试验。DM0/DM1 在实物左侧，
  对应训练模型的 `rf`（机体 +y）；DM2/DM3 在实物右侧，对应训练模型的
  `lf`（机体 -y）。用户根据闭链示意选择 B：DM1/DM3 分别驱动左右侧
  CAD“前”长臂（约 210 mm），DM0/DM2 分别驱动 CAD“后”短臂（约
  113 mm）。这是现场待核的机械判断，与 H7 当前“偶数槽为前、奇数槽为后”
  的旧假设相反。训练模型中的 `lf1/rf1` 是虚拟膝关节，不能直接当作某台
  DM 的实体关节名。最近的 DM2 +5° 试验因板端保护中止，不计为通过。
- 输入臂辨识补充：210 mm 长臂上也有距髋约 113.4 mm 的中间闭链销轴；
  因此不能只用“电机轴到第一个销轴的距离”区分长短臂。应核对整根刚性臂
  的远端连接与完整闭链拓扑；其他项目的 front/rear 名称不作为本机换槽依据。
- 旧观测的数值复算、IMU 方向、两侧来源和慢速髋方向有证据，但其闭链
  前后输入轴顺序建立在旧假设上。选择 B 后，旧数值复算不再证明实体映射
  正确；必须重新核对 DM 槽位、位置符号、精密零点、虚拟膝绝对几何、
  Jacobian 和轮速比例。四台 DM 非零方向及完整闭链力矩尚未通过。
- H7 没有轮地接触力输入，也没有直接机身高度测量。首次接管使用人工事件，
  成功高度由独立现场观测确认；不能把人工事件称作自动接触检测。
- 历史训练配置、真实闭链机构与气弹簧、地面摩擦存在差异；完成数值对照
  不等于物理起立成功。

## 控制架构

新增独立执行模式，保留 2701 失能诊断、USB `SET_TORQUE` 和关节台架模式。
电脑只负责 checkpoint 加载、CPU 推理、人工接管指令、记录与停止；
板端独占电机输出。新模式与其他输出模式互斥，启动需新的 session、匹配
的模型与接口标识、遥控“左下后左上＋右下”新鲜使能、六台电机在线、
观测有效和已确认的台架参数。上电、会话结束或故障后均失能；保持拨杆
上档不能自动重启。

新 USB 帧沿用现有版本、CRC 和序号规则，定义独立的 `START`、`SAMPLE`、
`ACTION`、`CONTACT_CONFIRM`、`STATUS`、`STOP` 类型与布局号，避免旧工具
误连。`SAMPLE` 包含板端时间、样本序号、25 维观测及 125 维历史；
`ACTION` 必须引用当前会话及当前样本，六值有限，且在下一个 10 ms 采样
前被 H7 接受。`CONTACT_CONFIRM` 引用正在显示的样本序号，仅允许一次：
H7 在下一个策略边界标记“本拍首次接地”，这一拍仍输出零动作，随后一拍
才接受非零 actor 动作。接管前主机对每帧回复全零动作，维持相同的通讯
时限检查和历史更新。接管事件、首个非零动作的样本号均写入日志。
这里的“零动作”是六维策略输出为零；腿部 PD 仍会朝默认关节角施力，
不能将其当成六路电机零力矩。地面接触彩排和实机保护按实际 PD 力矩评估。

H7 每 2 ms 取同拍电机/IMU 新鲜状态，构造虚拟关节位置、速度和闭链
Jacobian；每 10 ms 更新策略观测及历史。按 B 映射，实物右侧（训练 `lf`）
的 CAD 前/后输入分别来自 DM3/DM2，实物左侧（训练 `rf`）分别来自
DM1/DM0。用户确认 B 的 CAD 长/短臂对应优先，同时原四路 `dm_sign` 和
`dm_zero` 数值按槽保持。原固件另有“偶数槽加 π 减 2.476872、奇数槽减
0.667595”的角度约定；当前候选据此令 CAD 前角取奇数槽变换、CAD 后角
取偶数槽变换，并同步速度和训练侧复算。原代码的“前/后”文字标签不作为
CAD 长/短臂证据。用户提供 SolidWorks 原图并确认它与 125 帧失能采集
为同一“电机软件原始零位、机身平放、后摆”姿态，尺寸起点为髋电机轴心；
图中右髋到轮轴为后 319.93 mm、下 107.49 mm。原逐槽 CAD 角常数直接换轴
只预测后 279.85 mm、下 95.24 mm，因而不再沿用。使用同一训练 XML 的
闭链几何，在保留 `dm_sign`/`dm_zero` 数值和 B 实体轴身份的前提下，
单姿态拟合得到候选 CAD 角偏置：奇数槽 `0.8138714045` rad，偶数槽
`2.3227884081` rad；右侧 CAD 轮轴端点数值复算与图示尺寸一致。
再从原图读取髋轴像素 `(313,266)`、前长臂末端 `(662,70)`、后短臂末端
`(400,466)`，独立换算的训练输入角为 `-67.404°/-75.259°`，与端点拟合角
分别相差 `0.249°/0.279°`。三个中心各坐标按 ±3 像素扰动时，差值均落在
图像读数区间内；记录见同一证据目录的 `b-zero-fit-image-check.json`。
这是一处 CAD 姿态的几何拟合和同图角度校核，并非实物尺量或方向标定；左侧绝对零点、
非零电机方向及 Jacobian 仍须独立核验。原图和计算见
`H7_clion/captures/20261001-solidworks-zero-geometry-01/`。
动作先裁剪到训练接口范围，
腿目标为 `default + 0.5 * action`，轮目标速度为 `10 * action`。
腿 PD 使用 `Kp=10, Kd=1`，轮使用 `Kp=0, Kd=0.1`；虚拟力矩限幅为
`[40,40,3.9,40,40,3.9] N·m`。B 对应的闭链力矩候选映射按 USB
逻辑顺序为：

```text
USB0 =            J_rf_rear  * tau_rf1
USB1 =  tau_rf0 + J_rf_front * tau_rf1
USB2 =           -J_lf_rear  * tau_lf1
USB3 = -(tau_lf0 + J_lf_front * tau_lf1)
USB4 =  tau_rfwheel
USB5 = -tau_lfwheel
```

上述公式以用户选择的 B 和旧驱动极性为前提，是虚功变换的候选值；
在各 DM 失能反馈、单槽受控方向、零位和 Jacobian 完成实物核验前，
不能直接用于整机非零输出。驱动边界已有极性处理，应用层不得重复翻转。
板端按实测支持范围对六路
实体输出另行限幅，并记录虚拟/实体力矩与限幅次数。首次非零策略前，
四腿映射、精密零点和后关节安全方向需完成单槽台架验收；若证据不足，
本模式只允许零输出检查，不把保护阈值逐次自动放大。

## 保护与故障

输出由板端状态机控制。每个 2 ms 周期检查 CAN/电机/IMU 新鲜度、遥控
在线及档位、USB 连接、周期遗漏、几何求解、Jacobian 和所有浮点数、
力矩反馈与倾角。按用户后续明确要求，位置和速度只记录，不设置数值阈值门控。
动作错序、重复、缺拍或迟到即停，
不得沿用上次动作；`STOP` 和遥控失能优先于排队中的动作。执行模式使用
比现有 100 ms 通用 USB 力矩看门狗更严格的逐策略步时限。板端发送零力矩
并撤销 DM 使能，记录首次故障原因与最后有效样本；人工接管命令不能解除
任何故障。主机同时保留停止与异常退出后的失能确认，但主机检查不代替
板端保护。

实体力矩保护阈值需要从实测单关节与模型数值对照确定，写入版本化试验配置并在
固件/主机两侧核对。现有轮减速比保持 15.5；不以设计文件把
`LOWER_OBS_MAPPING_VERIFIED` 改为 1。

## 验证顺序与证据

1. 保存 H7 当前源码、ELF/板上固件身份及训练仓工作区差异的版本化快照；
   核对 checkpoint SHA-256、六电机参数和现有 2701/台架功能基线。
2. 先在失能状态下现场标识每侧 CAD 前长臂/后短臂对应的 DM 反馈槽，
   核对 B 与实体运动学，并重建前后角度的符号、零点和速度映射。
   以真实采集回放对照训练侧观测、actor、虚拟 PD 和闭链映射；验证
   首帧、历史、人工接管边界、丢包/超时、非有限数及 STOP。编译 H7，
   记录 map 内存、时序与主机测试结果。代码变化后重新判定旧证据有效性。
3. 烧录前核对遥控双下、六台在线/失能、六路目标为零；烧录后读回固件并
   在失能、零输出下验证新协议与实际 100/500 Hz 时序。
4. 逐个完成四 DM 的受控非零方向、闭链虚功映射与保护停机验证。所有
   单槽结果、未通过结果和现场观察分别保存；零点/虚拟膝几何问题在
   全策略动作前处理。不得把此前中止的 DM2 +5° 试验记为通过。
5. 机身有防跌支撑、人员远离连杆，先运行零动作接地流程，再由现场人员
   确认轮接地并发送一次接管事件，记录首轮短时起立。每次异常都先停机、
   核对失能及机械状态，分析后才进入下一次，不自动重试或增加输出。
6. 与训练仓正式 MuJoCo 起立结果对照，并用现场独立高度/姿态证据、
   板端 500 Hz 日志、主机 100 Hz 日志和用户观察判定最终结果。

每次试验保存输入 checkpoint、源码/固件/配置哈希、执行时间、命令、
工作区状态、退出码、原始遥测及结论。若物理映射或安全门未通过，应
明确停在对应阶段，不声称完成整机起立。训练仓根目录 `logs/` 只读；
不启动新训练或 TensorBoard。
