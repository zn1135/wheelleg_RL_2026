# model_5849：H7 适配交付包

本包交付给 H7 部署负责人，用于导入网络、适配 39 维接口和板端数值核对。模型是当前最新的 39 维 multimode 策略（2026-10-17 平地跟踪续训终态），训练域为无限平地、命令包线 vx ±1.5 m/s、yaw ±1.5 rad/s。**不能直接替换现有 25/125 维、100 Hz 的旧 H7 网络。** 固件适配、板端耗时和真机验证尚未完成，部署负责人核对状态为“待确认”。本次不改 H7 控制代码、物理极性或零点。

本包与 2026-10-15 的 `model_3023` 交付包结构相同，替换为当前最新模型与参考向量。

## 文件

| 文件 | 用途 |
|---|---|
| `model_5849_opset13.onnx` | 交给 Cube.AI／ST Edge AI 导入的网络；208039 字节、权重内嵌 |
| `model_5849_opset13_export.json` | 模型校验值、接口、工具版本和数值检查记录；路径以仓库根目录为基准 |
| `model_5849_opset13_reference_vectors.npz` | 256 组输入及对应 PyTorch 输出，键为 `obs`、`actions` |
| `reference_inputs.csv` | 同一组输入，256 行×39 列，无表头、无行号 |
| `reference_actions.csv` | 同一组期望输出，256 行×6 列，无表头、无行号 |
| `SHA256SUMS` | 本目录其他六个文件的 SHA-256，用于确认传输前后文件一致 |

CSV 的第 n 行输入对应第 n 行期望输出，每行是一次 batch=1 推理。数据已是模型输入，无需再乘观测缩放系数；这组随机数只用于网络数值核对，不能下发为机器人运动指令。CSV 与 NPZ 转换后 float32 数值逐项一致。

## 接收与适配步骤

1. 获取本目录和上面的说明文档。拉取含交付包的 Git 提交时应能看到本表全部文件；直接发送文件时也应附上说明文档。
2. 在本目录执行 `sha256sum -c SHA256SUMS`。成功判据：每个文件均显示 `OK`。
3. 使用协作者实际安装的 Cube.AI／ST Edge AI 版本导入 ONNX，记录工具版本、芯片、生成配置、Flash/RAM 占用和导入报告。成功判据：导入通过，并确认单输入 39 个 float32、单输出 6 个 float32；本次尚未验证具体版本能否导入。
4. 先仅运行网络，逐行输入 `reference_inputs.csv`，与 `reference_actions.csv` 比较六个输出。当前导出的电脑端最大绝对误差为 `3.814697265625e-06`，采用的容差为 `1e-4`；板端先以同一容差核对并记录实际最大误差，超出时查明差异。此步骤不连接策略输出到电机。
5. 按完整说明实现观测、动作重排和 50 Hz 调度，逐项核对单位、默认角、实体关节映射、模式标志及图外控制。成功判据：形成双方确认的接口记录，并记录最坏推理和完整控制周期耗时，确认满足 20 ms 策略周期及 2 ms 内环调度要求。
6. 板端数值和接口核对完成后，再单独安排实机验证并记录结果。已有静站仿真条件为平地、NORMAL、零速与 vx=1.5 m/s；这一证据不等于实机或全模式验证。
