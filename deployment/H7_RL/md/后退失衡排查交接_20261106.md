# 后退失衡排查交接（2026-11-06）

> **2026-11-06 后续修正（以此为准）**：下文为17:37历史快照，不是当前已证实根因。作者确认pos_target=.7有意设置，设0仍会失稳，本轮保留。负轮矩不能仅凭符号认定“最大制动”；必须结合实际轮速与同坐标电流/力矩判断机械功率。旧记录将机身质量与含腿/轮总质量混比所得“重约24%”不能作为本机模型质量错误依据，未修改质量或标定。旧“高速后退轮矩不足”的因果结论待5002反馈链复核。
>
> 已修正十态MPC与offset工作点坐标不一致；与原LQR采用相同静态平衡假设，未证明实际平衡点正确，更未证明后退故障消失。新增固定48通道5002采集真实电机反馈及请求，详见file-guide顶部；当前双宏1，十态N20/250Hz/100轮、四态N10/500Hz/100轮，覆盖旧开关/参数快照。

本文只总结本轮“后退/带速反向时 pitch 发散、机体速度突破目标甚至到 3.2～3.4 m/s”的排查过程、试过的方法、当前代码状态和未确认项。参数以当前源码为准；本文数值是 2026-11-06 17:37 前后的快照。

## 0. 结论摘要

- LQR 和 MPC 都有后退失衡；不是某一条控制器独有的问题。
- 高速后退失稳时，最终轮矩 **-4.79/-4.79 Nm** 已打满，LQR 候选可到 **-20.8 Nm**；髋 Tp 约 **-17.6 Nm**，限幅 54 Nm，仍有余量，但髋不能产生水平制动力。
- 速度指令限幅只改“目标”，不是实际速度限制；目标 -2.8 时实际仍到 -3.2～-3.4，轮已用最大制动仍拉不住。
- 腿角平衡点确实随腿长移动（0.155m 约 -0.027、0.219m 约 +0.005），固定 `leg_trim=0` 会让前进/后退相对“平衡中点”不对称；但补了长度相关 offset 后，高速后退失衡仍然存在。
- 截至本文，未找到纯软件参数能同时解决“低速腿角对称”和“高速后退轮矩不足”的办法。下一步应做轮矩/质量包线确认，或轮-髋解耦/分配的专项验证；不再在限速、N、频率、优先级上循环。

## 1. 现象与关键数据

### 1.1 高速后退失稳

一次典型失败（N=20、250Hz 数据中的 target -3.0 段）：

| 量 | 值 |
| --- | --- |
| 目标速度 | -3.0 m/s |
| 实际 ds | 约 -3.2～-3.4 m/s |
| pitch | 到 -0.62 rad，pitch rate 约 -4 rad/s |
| 最终轮矩 | -4.79 / -4.79 Nm（限幅） |
| 原 LQR 轮候选 | 约 -20.8 Nm |
| Tp | 约 -17.6 Nm（髋限幅 54） |
| 髋限幅前/实际 | 未打满（5001 数据中相等，约 0.8/10.9 Nm） |
| backend | 在 1/2 间切换，reason 6/2/7 都有 |

结论：轮在最大制动，仍然无法在目标时间内降速；髋有余量但不能增加水平力。

### 1.2 速度指令与实际速度

- 公共速度目标改成过 +3.0/-2.8（当前大机源码又有变化，见 §3）；
- 反向超速帧中，实际 ds 可到 -3.4，目标只有 -2.8；
- 这说明 `velocity_target` 只是目标，不是物理限速；LQR/MPC 用有限增益跟踪，实际速度可以冲过去；
- 在另一份较低速数据里，反向后超速 1,473 帧，最终轮均值只有约 -0.98/-0.82 Nm，轮没有打满；说明低速段不是轮矩不够，而是速度/腿角环没有用力刹车。

### 1.3 腿角平衡点

5001 静止段（target≈0、|ds|<0.05）按腿长分箱：

| 腿长 | 左中点 | 右中点 |
| --- | --- | --- |
| 0.155/0.148 | -0.027 | -0.028 |
| 0.179/0.173 | -0.018 | -0.021 |
| 0.219/0.215 | +0.005 | +0.014 |

- 左右腿长接近时，左右中点基本一致（差 0.001～0.009 rad）；之前 -0.033/-0.013 的 0.02 差是混了不同腿长/工况，不可直接当左右 trim。
- 中点随腿长移动约 0.03 rad；固定 0 不可能是所有腿长的平衡点。
- 低速前进/后退相对中点的偏差：低腿长前进约 -0.37、后退约 +0.42；后退看起来更大，主要是目标 0 在平衡中点前方约 0.03 rad，控制器围绕 0 对称，而不是围绕实际中点。

## 2. 试过的方法

### 2.1 VOFA 诊断布局

- 4001：LQR 后退诊断，含轮矩分项、轮限幅前/后、pitch、速度。
- 5001：后退诊断，含世界左右腿角/角速度、S/DS/pitch 三列贡献、F/Tp、髋限幅前/实际、最终轮/原 LQR 候选；当前启用。
- 3002：自起排查；2005：双 MPC 候选对照；MPC 健康布局：后端/迭代/残差/solve/周期/选定与基线输入。
- 这些布局都只能异步观测，不是严格同拍；换布局必须人工改 `#if 0/#if 1`，不能按旧表解析新 CSV。

### 2.2 十态 MPC 步数与 100 轮上限

| 版本 | 结果 |
| --- | --- |
| N=30，max_iter=100 | solve 中位 4.25ms，投入段 88% reason 6，MPC 实际采用只有 0.3%；计划迟到，回退 LQR |
| N=27 | 投入段 adopted 约 62%，solve 4.18ms，reason6 2,588；仍迟到 |
| N=20 | adopted 约 82%，solve 3.18ms，period 4.0ms（250Hz），reason6 约 0.8%；MPC 时序正常 |

结论：100 轮不是瓶颈（实际迭代 22～26，最大 36）；N=30 在 2ms 节点/4ms 激活下不可用；N=20 能稳定跑 250Hz，但**高速后退仍失稳**，说明窗口/频率不是根因。

### 2.3 250Hz/4ms 调度、2 节点预测、热启动

- `BALANCE_MPC_SOLVE_DIV=2`：计划激活改为快照 +4ms，状态预测 2 节点，参考前移 2 节点；`balanceMpcTask` 周期 4ms。
- `MPC_Shift_Warm_Start`：每次求解前把上次 z/y 前移 `BALANCE_MPC_WARM_SHIFT=2` 节点，仅改初值，不改验收/最优解。
- 结果：N=20 的 solve 3.18ms、period 4.00ms、adopted 82%，时序问题解决；但后退失败仍在，说明 MPC 步数/频率/热启动不是根因。

### 2.4 MPC 任务优先级

- 按作者要求从 `osPriorityNormal` 提到 `osPriorityHigh`（与 RL policyTask 相同，低于 actuation）。
- 实测变差：solve 仍约 4.19ms，VOFA 帧间隔 p95 30ms、最大 296ms；11.3～11.53s 出现 LQR 仍投入、选定轮矩 1.33/-4.79，但最终轮持续 0；属于输出/发送路径失力，不是控制决策为零。
- 已退回 `osPriorityNormal`；Normal 下数据恢复 200Hz、输出失力消失。High 不要再试；如再试只能 AboveNormal，并先验证输出路径。

### 2.5 公共速度指令非对称限幅

- 增加 `vel_max_rev`，`Rc_Command_Update` 按摇杆符号分别乘 `vel_max`/`vel_max_rev`。
- 曾设 +3.0/-2.8；当前大机源码为 +3.0/-3.0，小机 +3.0/-2.8（以源码为准）。
- 结果：目标限幅不能限制实际速度；高速段仍到 -3.2～-3.4，轮 -4.79；低速段也不是轮饱和，而是速度/腿角环制动力不足。
- 结论：限速是目标钳位，不是物理速度限制；不能作为根因修复。

### 2.6 腿角零位/平衡点（CKP `LQR_OFF_WBR`）

- CKP 的 `LQR_OFF_WBR` 是按腿长给左右腿角平衡点（多项式），LQR 目标用它，不是 0；CKP `body.leg_ang = leg.ang + pitch`。
- 本机 `x[THL] = virtual_leg_angle - pitch`，`leg_trim=0`，`x_eq=0`，没有长度相关平衡点。
- 已加 `LQR_Offset_Eval`（`lqr_balance.c`），默认用本机实测中点线性拟合：
  - 左 `0.500*L - 0.1045`，右 `0.627*L - 0.1208`；
  - `leg_trim` 仍 0；AIR 时 off=0；LQR/MPC 共用 target；
  - `LQR_OFF_USE_CKP=1` 可切 CKP 多项式（带负号映射）。
- 结果：低速腿角对称有改善迹象，但高速后退失败仍在；0.30m 以上是线性外推，0.34m 时目标约 +0.067/+0.092，而实测腿角只有约 0.01，外推很可能过大。
- 结论：平衡点 offset 解释低速腿角不对称，不是高速失稳的解；高腿长不要外推。

### 2.7 CKP 对比

- CKP 的四髋分配器只做 F/Tp → 四个髋，不联动轮；和本机 `Leg_Balance_Apply_Inputs` 同一层，不是轮-髋分配。
- CKP 轮限幅：`M3508_TO_TORQUE=3347.1`，16384 raw ≈ 4.9 Nm，和本机 4.79 Nm 接近；CKP `BODY_MASS=20.534kg`，本机 25.544kg，重约 24%。
- CKP 的 `LQR_OFF_WBR` 是平衡点，不是提高轮矩；不能解释/解决本机高速后退的轮矩不足。
- 直接抄 CKP 的 off 系数不可靠：CKP `ang+pitch`、本机 `virtual-pitch`，角定义/机器不同；代码里保留开关，但不是默认。

### 2.8 轮-髋分配/解耦（仅分析，未实施）

- 模型 B 显示髋对 pitch 角速度的权限约为轮的 8.6 倍/Nm；髋限幅 54，当前只用约 17.6，理论有余量。
- 但一步 QP 试算只给出约 1.3 Nm 髋修正，pitch 几乎不变；髋权限要跨多个 2ms 节点累积，一步分配太短。
- 40ms 的 MPC 仍在 3.2 m/s 失败；轮已 -4.79，分配最多把轮从 pitch/腿角里解放出来，不能增加总水平制动力。
- CKP 没有轮-髋联动；要试只能做本机专项（多步 QP、终端约束或轮/腿解耦），不是照搬 CKP。

### 2.9 数据/日志问题

- 多份 CSV 出现同一时间戳混两段工况、HAL 时间回绕/拼接、49,999 行截断等；不能把时间轴当单一 run。
- 一次记录应只做一个腿长/一个工况；至少注明布局号（5001 的 46 号是位图，不是布局号；MPC 健康的 46 号是 N）。
- 异步 VOFA 不是严格同拍快照；分项之和、实际速度与目标不能要求逐行严格闭合。

## 4. 已排除/基本确认

1. **不是优先级本身**：High 会饿死 comm/VOFA 并出现最终轮 0，Normal 恢复；但后退失稳仍在。
2. **不是 MPC 求解迟到**：N=20 已 250Hz、solve 3.18ms、adopted 82%、reason6 约 0.8%；后退仍失稳。
3. **不是速度指令限幅**：目标 -2.8 实际到 -3.2～-3.4；命令钳位不限制实际速度。
4. **不是四态 MPC/腿长环单独失败**：F/Tp 仍有输出，最终轮打满；高度/roll 后端不是主因。
5. **不是单纯腿角零位**：平衡点随腿长确实存在，offset 影响低速对称；高速失败仍在，且高腿长外推无依据。
6. **不是轮没出力**：高速段最终轮 -4.79 已到限幅，LQR 候选 -20.8；是轮矩上限/包线，不是输出被截为 0。

## 5. 未确认/待验证

1. **实际轮矩**：4.79 Nm 是否在电池压降、电流限、传动效率、轮胎打滑下真的能达到；需要台架/称重/电流记录。
2. **质量/质心**：25.544kg 与 CKP 20.534kg 的差异；后退制动余量是否根本不够。
3. **腿角坐标/符号**：本机 `virtual-pitch` 与 CKP `ang+pitch` 的符号关系；K 表 leg 列是否与状态定义一致。
4. **速度环增益/腿角项抵消**：低速反向后超速时最终轮只有约 1 Nm，为什么不用更多轮矩；需要 DS/腿角分项和 K 的逐项核对。
5. **轮-髋解耦/分配**：多步 QP 或终端约束是否能在轮打满时保住 pitch；一步 QP 已证明太短。
6. **高腿长 offset**：0.30m 以上没有实测中点；当前外推可能有害。

## 6. 建议下一步

按优先级：

1. **台架确认轮矩/质量**：记录电池电压、电流、实际轮端力矩/称重；确认 4.79 Nm 是否真实可用。若实际远低于 4.79，先修电气/传动，不要继续调控制。
2. **确认包线**：若 4.79 Nm 真实，25.5kg 在 3.2 m/s 的制动余量不足；要么提高轮矩/换传动/减重，要么接受更低速度包线。限速不是“软件技巧”，是执行器包线的结果。
3. **软件只剩专项**：轮-髋解耦/多步分配，且只能把轮从 pitch 里解放，不能增加总制动力；先离线验证，再上机。
4. **腿角 offset 先收敛**：把 `LQR_Offset_Eval` 限制在实测 0.15～0.22，或暂时关闭；先做 0.16/0.22 的静止+低速前后干净数据，再决定是否保留。
5. **日志规范**：一次一个文件、一个腿长/工况；标注布局；不要把多段 run 拼在一个 CSV 里。
