## 3. 两种电机顺序：必须分别处理

反馈、位置/速度观测、PD目标与诊断的内部顺序：

```text
[lf0, lf00, rf0, rf00, lfwheel, rfwheel]
 左前  左后  右前  右后   左轮     右轮
```

网络原始action、`action_state.a`和`observation.last_action`顺序：

```text
[lf0, lf00, lfwheel, rf0, rf00, rfwheel]
 左前  左后    左轮   右前  右后    右轮
```

`RL_Action_Index()`统一保存内部索引到原始action索引的映射：

```text
[0, 1, 3, 4, 2, 5]
```

| 内部电机 | 内部索引 | 原始action索引 | 位置obs | 速度obs | 历史action obs |
| --- | --- | --- | --- | --- | --- |
| 左前lf0 | 0 | 0 | 10 | 16 | 22 |
| 左后lf00 | 1 | 1 | 11 | 17 | 23 |
| 右前rf0 | 2 | 3 | 12 | 18 | 24 |
| 右后rf00 | 3 | 4 | 13 | 19 | 25 |
| 左轮lfwheel | 4 | 2 | 14固定0 | 20 | 26 |
| 右轮rfwheel | 5 | 5 | 15固定0 | 21 | 27 |

生成目标与写入历史观测都用同一映射。网络封装不重排输出；历史保存原始网络输出，不保存位置目标、轮速目标或力矩。这不是旧版左右腿角色交换。

## 4. 坐标、反馈与三种角度基准

### 4.1 机体与IMU

模型机体系：+X前、+Y左、+Z上。实机以作者标记的机头方向为前；站在机尾面向机头时，leg_l在左手边。该对应关系仍应与模型CAD共同复核。

当前HI229映射：

```text
gyro_body = [-gyro_sensor_Y, +gyro_sensor_X, +gyro_sensor_Z] × π/180
quat_body = [w, -qy, +qx, +qz]，随后归一化
gravity_body = R(quat_body)^T × [0,0,-1]
```

RL不直接使用欧拉角或原始加速度作为姿态观测。水平静止时gyro接近0、gravity接近[0,0,-1]；四元数可以保留任意水平航向，不要求等于[1,0,0,0]。

| 从水平姿态做动作 | 动作时角速度 | 保持倾斜时重力 |
| --- | --- | --- |
| 低头 | ωY正 | gX正 |
| 抬头 | ωY负 | gX负 |
| 左侧降低 | ωX负 | gY正 |
| 右侧降低 | ωX正 | gY负 |
| 水平左旋 | ωZ正 | 仍约[0,0,-1] |
| 水平右旋 | ωZ负 | 仍约[0,0,-1] |

此前六动作CSV与此符号表一致，仅证明该次方向核对通过，不替代全部安装/动态校准。

### 4.2 固件反馈到模型原生角

腿电机原始CAN反馈在dm.c中已经进行驱动极性处理、rad/rad/s解码和机械零偏叠加；当前部署只保留单圈`pos_zero_rad`，不再进行连续计圈。RL取此实体电机角，不取虚拟腿角，也不额外加π。

定义：

```text
p_fw   = 驱动已标定的pos_zero_rad，rad
v_fw   = 驱动已处理方向的vel_rad_s，rad/s
s      = machine.rl.motor_sign
z      = machine.rl.motor_zero

q      = s × (p_fw - z)
dq     = s × v_fw
tau_fw = s × tau_model
```

驱动层随后仍应用已有dm_sign/dji_sign输出标定。RL的s是相对于驱动当前坐标的额外转换，不能根据模型右侧轴为−Y就直接重复反号。

当前软件假设：`motor_sign=[1,1,1,1,1,1]`、`motor_zero=[0,0,0,0]`。当前代码没有写入新的实测零偏；作者反馈目前无明显问题，不等于这两个数组已经有逐电机标定记录。

轮速度已按`RPM × 2π/60 ÷ 15.5`换算到轮轴，再乘对应RL符号；不重复除齿比。模型两轮位置观测固定0，不需要轮位置零点。

模型左侧驱动轴为+Y，右侧为−Y。固定机身和腿、两轮同向前滚时，模型轮速应左正右负；同向后滚时左负右正。

### 4.3 q=0、q_reference、q_nominal与obs=0

| 名称 | 含义 | 在代码中的用途 |
| --- | --- | --- |
| 原生q=0 | 模型定义的几何零位 | 确定实体杆件角度坐标 |
| q_reference | XML的qpos0，装配参考角 | 腿目标角限幅中心 |
| q_nominal | 训练默认微蹲姿态的原生角 | 位置观测减去它，位置目标加上它 |
| motor_zero | 实机驱动坐标到模型原生坐标的额外零偏 | 转换p_fw到q |
| 位置obs=0 | 当前q等于q_nominal | 网络看见默认站立关节位置 |

当前四腿常量，单位rad：

| 顺序 | q_reference | q_nominal |
| --- | ---: | ---: |
| 左前lf0 | -0.664720554 | -0.604720554 |
| 左后lf00 | +0.667594582 | +0.608324173 |
| 右前rf0 | +0.664720554 | +0.604720554 |
| 右后rf00 | -0.667594582 | -0.608324173 |

原生q=0时，前髋主腿杆的XZ投影朝机尾−X，后髋短摇臂朝机头+X。默认站立姿态则是主腿杆后下约34.65°、短摇臂前下约34.85°，两侧镜像；按模型几何，轮轴基本在髋轴下方约0.301m。这些是模型几何换算值，供训练同学核对CAD/默认姿态，不作为实机已标定记录，也不等同于目标机身高度0.30m。

默认姿态时四个q为上表q_nominal，位置obs[10:14]才为全0；不要求电机编码器原始读数为0。实际平衡时策略可能输出非零action，因此“能站住”也不要求位置obs为0。

q_nominal原定义来自训练仓`model.py::standing_motor_positions()`的闭链姿态。前关节CAD相对目标为左(0.06,-0.10)、右(-0.06,+0.10)，后链求解闭合。部署常量此前用同样的XML/定位点独立几何核算得到；训练同学应在3023对应环境中重新导出并确认完整数值及姿态截图。

已知姿态标定公式：`z_new = p_cal - s × q_cal`。当前s=1/z_old=0时，也可用`z_new = obs_measured - obs_expected`；标定后必须多姿态、重启检查单圈零点角，不能只在一个姿态凑零。

## 6. action、PD与最终下发

网络输出是无量纲原始动作，不是直接力矩：四腿生成位置目标，两轮生成速度目标。最终线性层没有tanh，部署也没有额外±1限幅。

对内部第i个腿电机，先取`a = raw_action[RL_Action_Index(i)]`：

```text
q_target = clamp(q_nominal[i] + 0.5 × a,
                 q_reference[i] - 3.14,
                 q_reference[i] + 3.14)

tau_model = clamp(60 × (q_target - q_current) - 2 × dq_current,
                  -40, 40)

tau_firmware = motor_sign[i] × tau_model
```

对两轮，取原始action[2]和action[5]：

```text
v_target = clamp(10 × a, -150, 150)
tau_model = clamp(0.1 × (v_target - dq_current), -3.9, 3.9)
tau_firmware = motor_sign[wheel] × tau_model
```

执行顺序：action索引映射→缩放/加默认角→裁剪目标→使用当前q/dq计算PD→裁剪力矩→还原固件方向→最终许可→发送。

PD反馈不使用obs中的速度缩放值；位置误差不环绕到±π。腿目标是以q_reference为中心限制±3.14，不是绝对角±π。训练腿D项是实际速度阻尼，不能直接换成现有PID的误差差分D。

`output_dispatch()`当前主体已恢复，正常情况下会进行有限性及最终许可检查，然后发送DM/DJI请求；无效或关闭输出时走零力矩分支。不能沿用标定期间曾注释下发主体的旧状态描述。

DM发送使用MIT力矩通道，MIT内部Kp/Kd设为0；H7已计算PD，不再让电机内部重复做同一个PD。RL腿限幅40Nm与MIT编码量程54Nm用途不同，不应把编码量程改成40。轮输出通过驱动将轮轴Nm按既有减速比/电流刻度换算，当前RL限幅3.9Nm。

## 7. 任务时序、投入和有效性

| 环节 | 配置/调用方式 | 说明 |
| --- | --- | --- |
| TIM6/执行基础拍 | 1ms/1kHz | 执行任务等待ctrl_tick_sem |
| RL模型采样/PD/正常下发 | 每2个基础拍，名义500Hz | MACHINE_RL_CTRL_DIV=2；间隔拍保持旧命令 |
| 策略推理 | 每20个基础拍，名义50Hz | MACHINE_POLICY_DIV=20；一拍action供10个RL子步使用 |
| 通信任务 | comm_task_body后osDelay(1) | 实际反馈更新还取决于CAN接收与调度，不等于每次控制都有新帧 |
| IMU任务 | imu_task_body后osDelay(1) | HI229去重后才发布新反馈，实际刷新由传感器决定 |
| VOFA后台 | background_task_body后osDelay(5) | UART DMA忙时可跳过；CSV行间隔不等于2ms或20ms |

这些是配置与软件步序，不是最新固件实测的逐次频率/抖动报告。

遥控模式：左拨杆上选择RL；右拨杆中请求投入，右拨杆上/下不请求投入。是否实际允许输出还由在线、反馈、姿态、故障、模型ready及总输出开关决定。

不投入仍可观测的条件是“RL已选中、源反馈可用、任务正常运行”；不要求engage=1。若没有选择RL，task_policy会清空观测；样本无效时构造失败也会发布全0无效obs，因此全0必须结合状态检查，不能直接解释为机械角0。

策略任务在短临界区复制最新样本和原始历史，在本地构造完整obs后发布，再调用网络。推理完成后复查模式及reset_count，避免在投入/退出清零期间返回的旧推理重新发布。

投入、退出、失能和失败会按相应路径清动作/目标历史。当前NORMAL不加200ms零力矩保持；训练地面起立的ground_start/前0.2s门控尚未部署。动作停更与投入后持续无有效动作分别有100ms看门狗。

固定配置直接使用；保留源反馈可用性、新投影/映射/obs/action/力矩结果检查、SDK动态I/O与返回值、故障和最终发送许可。configured是机型启用开关，不是固定参数合法性扫描。

## 8. 当前VOFA实际布局：有四路覆盖

总计43个float通道，后台固定赋值、一次发送，不按模式切帧。当前先执行`dbg[3+i]=obs[i]`，随后四个赋值覆盖ch35～38：

| 通道 | 当前实际内容 |
| --- | --- |
| ch0/I0 | 设备在线掩码 |
| ch1/I1 | 状态位 |
| ch2/I2 | 故障位 |
| ch3～34 | obs[0～31] |
| ch35/I35 | 左前原始固件连续标定角p_fw[0]，覆盖原obs[32]的jump |
| ch36/I36 | 左后p_fw[1]，覆盖原obs[33]的jump_target_height×5 |
| ch37/I37 | 右前p_fw[2]，覆盖原obs[34]的jump_state_time |
| ch38/I38 | 右后p_fw[3]，覆盖原obs[35]的ground_start |
| ch39～41 | obs[36～38] |
| ch42/I42 | 最近一次网络调用耗时us，仅网络SDK调用时间 |

因此当前CSV不能将ch3～41整体直接还原成完整39维网络输入；ch35～38是p_fw，不是模型q，也不是obs。网络内部obs本身未被这四个调试赋值修改。

标定时四腿对应关系：

| 电机 | 原始固件零点后单圈角 | 模型位置观测 | 由obs反算模型q |
| --- | --- | --- | --- |
| 左前 | I35 | I13 | I13−0.604720554 |
| 左后 | I36 | I14 | I14+0.608324173 |
| 右前 | I37 | I15 | I15+0.604720554 |
| 右后 | I38 | I16 | I16−0.608324173 |

仅在obs有效时使用上述反算；未选择RL而obs被清空时，不能反算。I35～38仍可用于观察驱动反馈，不代表策略采样有效。

I1状态位：bit0总电机使能、bit1跌倒、bit2/3双腿几何有效、bit4～7四髋使能、bit8 LQR投入、bit9 RL投入。bit9只表示软件投入状态，不能单独证明实际力矩已发出或实体执行成功。

如需记录完整网络输入，应手动注释四路p_fw覆盖赋值，再按完整obs布局发送；同步接收端通道表。保持现有固定赋值风格，不增加动态页面/选帧逻辑。
