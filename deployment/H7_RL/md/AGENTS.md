## §3 改动哲学

- **最小改动**：围绕已授权目标修改；作者要求“检查整个项目并统一”时，覆盖工程自有代码的同类问题，不只修改举例函数，不扩展到其他行为。
- **优化要有实际收益**：目标是减少重复运行开销、代码量和阅读负担。优先删除重复计算、重复判断、无效转传和无用状态；不能只把长函数拆成更多包装函数。
- **避免过度设计**：复用已有状态和标志，不为简单迁移增加通用框架、批次/版本状态、跨周期缓存管理或额外处理层。若无法降低开销并简化代码，说明取舍并撤回本次增加复杂度的方案，不影响作者已有修改。
- **结构与行为分开**：整理配置、移动计算或清理封装时保持公式、参数、坐标含义、限幅及状态切换语义；积分/滤波推进次数、控制先后顺序、固定dt替换等属于行为变化，单独说明和验证。
- **不默认保留旧路径**：无需为回退自动增加A/B开关、旧表、兼容别名或备用实现；作者确认只用当前方案时连同旧声明、字段、初始化和引用清理。已有明确保留的调试功能不因此删除。
- **删除先查实际用途**：按声明、赋值、读取、调用链、编译分支和回调注册追踪；“被复制/读取”不等于参与控制，“无直接调用”不等于没有中断或回调入口。在已授权清理范围内，确认无用途后一起删除过度封装、空回调、失效参数和旧宏。
- **改动可归因**：结构优化不顺带调参或改物理量；物理红线仍按§0.1执行。
- **CUBE MX 保护区**：`USER CODE BEGIN/END` 之外的代码不可手动修改，由 CubeMX 管理。

### 代码风格

- 普通局部变量沿用函数开头声明；仅供遍历的索引在对应for中声明并初始化，例如`for (uint8_t i = 0u; i < count; i++)`。循环后仍需使用的结果变量不机械搬入for。
- 工程自有结构体类型定义放在所属模块的.h；实例在.c中定义，私有实例保留static。相关状态复用已有结构体，不为一次转传新增上下文结构或一组全局调试量。
- 所有`if`、`else if`、`else`、`for`使用花括号，即使只有一个语句。
- 条件判断、赋值/计算、三元表达式、return和函数调用表达式写成一行，不按行宽拆开；控制块仍保留花括号和缩进。函数声明/定义的参数列表、数据表和初始化列表不必机械压成一行。
- 名称反映实际职责；注释说明核心计算、单位、状态切换和特殊原因，不逐行翻译代码。详细规范见§4。

### 源头校验与有效标志

- 原始反馈在解析/解算/发布端完成数值及可用性校验，成功后发布已有的online、valid或force_valid；失败清相应标志，不能携带上一拍的有效状态发布坏数据。
- 消费者直接判断所需标志，不逐层重复扫描已验证的IMU、关节、轮速、命令等数值；已有入口条件保证的固定指针、固定数组和固定周期，也不在内层反复防御。
- 删除重复检查前说明由哪个生产端或调用条件保证。生成新的投影、映射、观测、积分或力矩结果时，在生成处检查新结果；有效输入并不自动保证运算结果有效。
- 标志语义要准确：数据可用、力映射可用、模式投入请求和实际允许出力不是同一件事。优先复用现有标志，不为每个函数增加一套相同含义的valid。
- 作者2026-10-14明确要求：固定机器配置、编译选定的表和代码初始化的参数直接使用，不在初始化或实时循环扫描极性、零点、杆长、增益、Q/R、期限、速率等合法性。运行时检查集中在反馈可用性、实际运算结果、奇异/除零、SDK/协议边界和最终出力许可；功能开关、状态阈值、轨迹限速及输出限幅是算法行为，不能当成参数校验删除。
- 保留真正独立的检查：协议长度/数组边界、SDK动态返回、可选模型、几何奇异性、新计算结果、设备故障和实际发送许可。不以减少if数量为理由删除不同职责的判断。

### 公共配置与唯一计算入口

- 同一含义的参数只保留一个来源：公共遥控量程、腿长初值/速率归machine.rc；LQR、RL专属参数分别归对应配置。沿用现有config结构，不为配置访问增加中转层。
- 配置清理追踪到最终输出；只声明/赋值、只复制，或被固定为零的系数使其无效的字段，在授权范围内删除。不为凑数组维数保留不参与控制的增益槽位。
- `Rc_Command_Update`统一处理遥控死区、归一化、命令量程、拨轮腿长累加/限幅和模式解码。LQR读取以米为单位的公共rc.len；当前RL39静站按训练契约使用固定零速度和machine.rl.height，不把公共遥控指令硬套入模型。模式消费者直接读rc.mode，不再解码拨杆。
- 公共命令限幅在公共入口完成，不在LQR/RL另设同义量程。命令限幅、模型训练缩放/裁剪、几何/K表求值范围和执行器力矩限幅用途不同，不因名称相似强行合并。
- 仅转调另一个入口且没有实际消费者的包装、被函数忽略的参数、空回调不保留为假扩展点。作者明确保留的接口按“当前预留”记录，不能虚称已在运行。

### 固定周期、计算复用与执行链

- 各算法使用对应的MACHINE周期宏，不恢复无消费者的通用dt别名。不要给固定节拍链路再增加接收时间差dt、新帧判定或层层dt合法性检查。
- 离地估计按作者明确决定使用MACHINE_LQR_DT：旧反馈缓存也继续估力、滤波与计时，不恢复样本龄、四髋时间偏差、IMU停更或新帧门控。首次及失败恢复的差分初始化仍保留。
- 固定算法dt不替代设备失联、动作看门狗、硬件等待预算和耗时统计所需的真实时钟；源头接收去重与离地消费端的时间门控也应区分。
- 同一输入、同一物理含义的派生量在生成端算一次并复用。竖直加速度随IMU生成；弹簧力和重力补偿在执行拍准备，后续估力/控制消费本拍结果，不再重复调用模型。
- 公共限幅、角度环绕等纯数学助手统一维护在common/math_utils.h，不在各模块重写同义函数。合并前比较NaN/Inf、负零、端点、比较顺序和浮点舍入；不同语义的fmod/remainder、非有限清零或协议编码不能仅按名称替换。
- 复用先确认坐标、符号、单位、滤波状态和输入周期一致。实体弹簧力与输出抵消量不同，原姿态与pitch_world引用的重力值不同，不能为减少函数或缓存而混成一个值。
- RL执行公式以训练接口为准：四实体电机使用位置比例加实际速度阻尼，双轮使用速度比例。复用PID前核对D项、死区、角差环绕、内部/最终限幅及历史推进；现有PID的误差差分D不能按相同Kd数值直接代替训练的-Kd*dq，不增加未使用的PID对象或参数副本。
- 执行层负责读取反馈、安排计算和模式求解、发布诊断及统一下发；数学计算归已有算法模块。职责拆分应减少交叉读写和重复工作，不只追求主函数行数短。
- 滤波、速度融合和位移积分等有历史的计算须明确每周期推进位置；复位/接管不要通过重复执行整条估计链来实现。移动顺序或改变推进次数时单列行为差异并验证。
- 停车位移积分是LQR位置保持状态，不当作通用里程计。它依赖的目标、离地状态和投入基准要明确；不能未经确认把前一周期目标改为当前周期目标并称为纯重构。

### 任务与模块分层约束

- `freertos.c` 只负责任务创建、初始化调用、循环节拍、`osDelay` 和信号量等待；不放协议解析、运动学、控制器或电机报文代码。
- `imcalib/task/robot_control.c`负责共享状态定义、总初始化和动作清零；当前单模型RL没有模型切换入口。各task_*.c只实现对应任务的单周期逻辑，网络实际创建归ctrl_task_init→RL_Policy_Init。
- `commTask` 负责通信输入输出：DR16/DM/DJI 接收解析、状态刷新、在线/故障监测、使能和看门狗保护；HI229 姿态链路归 `imuTask`。它不等同于纯故障监视任务，因此命名使用 `comm`/`communication`，不要继续使用含义过窄的 `monitor`。
- defaultTask保留USB初始化，调用background_task_body处理普通VOFA与灯效。
- VOFA只在后台按源码固定通道赋值后统一发送一帧。换布局时手动注释旧赋值、启用新赋值，不增加模式/就绪标志选帧、页面状态或额外发送分支；允许保留注释通道参考。短临界区用于完整复制共享数据，UART DMA忙保护用于传输缓冲完整性，不因此搬到中断发送。
- `policyTask` 负责观测构建和 RL 策略推理；`actuationTask` 负责按实时节拍读取已准备状态并完成执行链路。
- **作者2026-10-12要求模式只解码一次**：`Rc_Command_Update()`解释拨杆并发布`rc_command.mode`（strategy/rc_enable/engage）；执行层和使能检查直接读取，禁止重复解码。左中选LQR、左上选RL、左下/离线失能，左中右上为补偿台架；出力许可、控制求解和分发仍归`task_actuation.c`。LQR 用 `lqr_balance.c` + `leg_balance.c`，RL 用 `rl_torque.c`。两套链路互不 include（除公共 `torque_output.h`），禁止在 LQR 模块引用 `rl_*.h`，也禁止在 RL 模块引用 LQR 状态。
- 五连杆几何和雅可比只能写在 `leg_solver.c/h`；姿态只能写在 `Attitude_Algorithm.c/h`；观测、策略、力矩映射分别归属对应 Algorithm 模块。任务文件只调用这些接口。
- DR16 字节解析只能归属 `dr16.c/h`。遥控死区、通道归一化和拨杆语义归属 `task/rc_command.c/h`（`commTask` 每拍填一次全局 `rc_command`，全机唯一解算点）；LQR / RL / 执行层只读 `rc_command`及其mode，禁止再各自 `DR16_Snapshot()` 解摇杆。不能让底层 DBUS 驱动直接操作电机。
- DM 的使能、失能、MIT 量化和报文发送归属 `dm.c/h`；DJI 零电流和轮电流发送归属 `dji.c/h`。任务层只调用语义清晰的接口，例如 `Dm_All_Disable()`、`Dji_All_Stop()`。
- 左拨杆下位的安全决策可以留在执行任务；具体 DM 失能和 DJI 零电流报文必须下沉到对应驱动模块。
- 不为了文件可读性随意新增 FreeRTOS 任务。只有当频率、优先级、截止时间或数据所有权确实不同，才新增任务；纯职责拆分优先使用模块和短函数。
- 任务职责不明确时，先向作者确认边界，禁止直接重排任务或跨模块搬运主体代码。

## §4 嵌入式代码注释规范

- 文件开头说明职责、输入输出与调用边界；关键函数说明核心流程、状态切换、单位和处理理由，允许必要的多行中文注释。
- 普通函数用一句概括，行内及结构体字段注释尽量简短；不把字数限制用于省略必要的物理含义或单位，也不逐行翻译明显代码。
- 控制链路改动同时补.c/.h注释，讲清输入/输出坐标、rad/rad/s/Nm单位、原始action与目标/力矩的区别、延迟对象、启动/退出语义及状态所有权；不能只留文件一句概括而省略关键函数含义。
- 不在行尾堆叠长篇解释；完整链路、推导背景和修改理由写入现有file-guide或历史记录。
- 修改职责或删除路径时同步相关注释，避免代码已经精简而注释仍描述旧分支。
